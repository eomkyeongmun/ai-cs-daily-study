# 네트워크 모델 - OSI 7계층 vs TCP/IP 4계층 모델의 각 역할과 프로토콜

## 핵심 개념

네트워크 모델은 서로 다른 시스템이 통신할 때 필요한 기능을 계층별로 나누어 설명하는 추상화 모델이다. 대표적으로 **OSI 7계층 모델**과 **TCP/IP 4계층 모델**이 있다. OSI 모델은 국제 표준화 관점에서 네트워크 통신을 7개의 세부 계층으로 나누어 설명하며, 교육과 문제 분석에 매우 유용하다. TCP/IP 모델은 실제 인터넷에서 사용되는 프로토콜 스택을 중심으로 구성된 모델이며, 오늘날 대부분의 네트워크 통신은 TCP/IP 기반으로 동작한다.

OSI 7계층은 아래와 같이 구성된다.

| OSI 계층 | 이름 | 주요 역할 | 대표 프로토콜/기술 |
|---|---|---|---|
| 7계층 | 응용 계층 | 사용자와 가까운 네트워크 서비스 제공 | HTTP, HTTPS, DNS, SMTP, FTP, SSH |
| 6계층 | 표현 계층 | 데이터 형식 변환, 인코딩, 압축, 암호화 | TLS, SSL, JPEG, JSON, XML |
| 5계층 | 세션 계층 | 세션 생성, 유지, 종료 | RPC, NetBIOS, 일부 TLS 세션 관리 |
| 4계층 | 전송 계층 | 종단 간 통신, 신뢰성, 흐름 제어, 포트 | TCP, UDP, QUIC |
| 3계층 | 네트워크 계층 | IP 주소 기반 라우팅 | IPv4, IPv6, ICMP, IPsec |
| 2계층 | 데이터 링크 계층 | 같은 네트워크 내 프레임 전달, MAC 주소 | Ethernet, Wi-Fi, ARP, VLAN |
| 1계층 | 물리 계층 | 전기적/광학적 신호 전송 | 케이블, 허브, 광섬유, 무선 주파수 |

TCP/IP 4계층은 일반적으로 다음과 같이 설명한다.

| TCP/IP 계층 | OSI 대응 계층 | 주요 역할 | 대표 프로토콜 |
|---|---|---|---|
| 응용 계층 | OSI 5~7계층 | 애플리케이션 서비스, 데이터 표현, 세션 처리 | HTTP, DNS, SMTP, SSH, TLS |
| 전송 계층 | OSI 4계층 | 프로세스 간 통신, 포트, 신뢰성 제어 | TCP, UDP, QUIC |
| 인터넷 계층 | OSI 3계층 | IP 주소 기반 패킷 전달과 라우팅 | IP, ICMP, IPsec |
| 네트워크 액세스 계층 | OSI 1~2계층 | 물리 매체 접근, MAC 기반 전달 | Ethernet, Wi-Fi, ARP |

두 모델이 중요한 이유는 네트워크 문제를 계층별로 분리해 분석할 수 있기 때문이다. 예를 들어 웹사이트 접속이 안 될 때, 물리 연결 문제인지, IP 라우팅 문제인지, TCP 연결 문제인지, TLS 인증서 문제인지, HTTP 애플리케이션 문제인지 계층별로 좁혀갈 수 있다. 또한 방화벽, 로드 밸런서, 프록시, VPN, 컨테이너 네트워크, 클라우드 네트워크 서비스를 이해할 때도 계층 구조가 기본 사고 틀이 된다.

## 내부 동작 원리

네트워크 통신은 송신 측에서 상위 계층 데이터가 하위 계층으로 내려가며 헤더가 추가되고, 수신 측에서는 하위 계층에서 상위 계층으로 올라가며 헤더가 해석·제거되는 방식으로 동작한다. 이를 **캡슐화(encapsulation)** 와 **역캡슐화(decapsulation)** 라고 한다.

예를 들어 사용자가 브라우저에서 `https://example.com`에 접속하는 과정을 계층별로 보면 다음과 같다.

```text
[응용 계층]
브라우저가 HTTP 요청 생성
GET / HTTP/1.1

        ↓ TLS 암호화 및 세션 처리

[전송 계층]
TCP 세그먼트 생성
출발지 포트: 임시 포트
목적지 포트: 443

        ↓

[인터넷 계층]
IP 패킷 생성
출발지 IP: 클라이언트 IP
목적지 IP: 서버 IP

        ↓

[데이터 링크 계층]
Ethernet 프레임 생성
출발지 MAC: 클라이언트 NIC
목적지 MAC: 게이트웨이 또는 같은 LAN의 대상

        ↓

[물리 계층]
전기 신호, 광 신호, 무선 신호로 전송
```

수신 측에서는 반대로 동작한다.

```text
물리 신호 수신
  → Ethernet 프레임 해석
  → IP 패킷 확인
  → TCP 세그먼트 재조립
  → TLS 복호화
  → HTTP 요청을 웹 서버 애플리케이션에 전달
```

계층별 데이터 단위는 다음과 같이 구분할 수 있다.

| 계층 | 데이터 단위 |
|---|---|
| 응용/표현/세션 계층 | Data 또는 Message |
| 전송 계층 | Segment(TCP), Datagram(UDP) |
| 네트워크 계층 | Packet |
| 데이터 링크 계층 | Frame |
| 물리 계층 | Bit |

주요 동작 흐름은 다음과 같다.

1. **DNS 조회**
   - 사용자가 도메인 이름을 입력하면 DNS를 통해 도메인 이름을 IP 주소로 변환한다.
   - DNS는 주로 UDP를 사용하지만, 응답 크기나 영역 전송 등 상황에 따라 TCP도 사용한다.

2. **라우팅**
   - 목적지 IP가 같은 네트워크에 있으면 직접 전달한다.
   - 다른 네트워크에 있으면 기본 게이트웨이로 전달한다.
   - 라우터는 IP 헤더의 목적지 주소를 보고 다음 홉을 결정한다.

3. **ARP 또는 Neighbor Discovery**
   - IPv4 환경에서는 IP 주소에 대응하는 MAC 주소를 찾기 위해 ARP를 사용한다.
   - IPv6 환경에서는 Neighbor Discovery Protocol을 사용한다.

4. **TCP 연결 수립**
   - TCP는 연결 지향 프로토콜이다.
   - 클라이언트와 서버는 3-way handshake를 통해 연결을 수립한다.

```text
Client → Server : SYN
Client ← Server : SYN + ACK
Client → Server : ACK
```

5. **TLS 핸드셰이크**
   - HTTPS에서는 TCP 연결 위에서 TLS 핸드셰이크가 수행된다.
   - 서버 인증서 검증, 암호화 알고리즘 협상, 세션 키 생성 등이 이루어진다.

6. **HTTP 요청/응답**
   - 브라우저가 HTTP 요청을 보내고 서버가 HTTP 응답을 반환한다.
   - HTTP/1.1, HTTP/2는 일반적으로 TCP 위에서 동작한다.
   - HTTP/3는 QUIC 위에서 동작하며, QUIC은 UDP 기반이다.

OSI 모델과 TCP/IP 모델의 관계를 그림으로 표현하면 다음과 같다.

```text
OSI 7계층                         TCP/IP 4계층

7. Application  ┐
6. Presentation ├───────────────  Application
5. Session      ┘

4. Transport    ────────────────  Transport

3. Network      ────────────────  Internet

2. Data Link    ┐
1. Physical     ┘───────────────  Network Access
```

핵심은 OSI 모델이 더 세밀한 설명 모델이고, TCP/IP 모델이 실제 인터넷 프로토콜 스택에 더 직접적으로 대응된다는 점이다. 실무에서는 “L4 로드 밸런서”, “L7 프록시”, “L3 라우팅”, “L2 스위칭”처럼 OSI 계층 용어가 널리 사용된다.

## 실제 시스템 연결

실제 시스템에서는 OSI와 TCP/IP 모델이 여러 구성 요소에 나뉘어 구현된다.

## Linux

Linux 네트워크 스택은 커널과 사용자 공간이 역할을 나누어 처리한다.

- **물리/데이터 링크 계층**
  - NIC(Network Interface Card), 드라이버, Ethernet, Wi-Fi가 담당한다.
  - `ip link`, `ethtool` 명령으로 인터페이스 상태를 확인할 수 있다.

- **네트워크 계층**
  - Linux 커널의 IP 스택이 라우팅 테이블을 기반으로 패킷을 처리한다.
  - `ip addr`, `ip route`, `ping`, `traceroute` 등이 관련된다.

- **전송 계층**
  - TCP/UDP 처리는 커널 네트워크 스택에서 수행된다.
  - `ss -tulpen`, `netstat`, `tcpdump` 등으로 포트와 연결 상태를 확인할 수 있다.

- **응용 계층**
  - Nginx, Apache, curl, SSH 서버, DNS 서버 같은 프로세스가 담당한다.
  - 애플리케이션은 소켓 API를 통해 커널 네트워크 스택과 통신한다.

예를 들어 Linux 서버에서 Nginx가 443 포트를 열고 있다면, 클라이언트의 HTTPS 요청은 다음 순서로 처리된다.

```text
NIC 수신
 → Ethernet 프레임 처리
 → IP 패킷 처리
 → TCP 세그먼트 처리
 → 소켓 버퍼 전달
 → Nginx worker process가 읽음
 → TLS/HTTP 처리
 → 응답 생성
```

## Nginx

Nginx는 주로 OSI 7계층, 즉 애플리케이션 계층에서 동작하는 웹 서버이자 리버스 프록시이다. HTTP 헤더, URI, Host, Cookie 등을 기반으로 라우팅할 수 있다.

예시:

```nginx
server {
    listen 443 ssl;
    server_name example.com;

    location /api/ {
        proxy_pass http://backend;
    }
}
```

이 설정은 HTTP 요청의 경로 `/api/`를 보고 백엔드 서버로 전달한다. 이는 L7 동작이다. 반면 Nginx의 `stream` 모듈은 TCP/UDP 프록시 기능을 제공하며, 이 경우 L4 수준의 프록시로 사용할 수 있다.

## AWS

AWS에서도 계층별 서비스를 구분할 수 있다.

- **VPC**
  - IP 주소 범위, 서브넷, 라우팅 테이블, 인터넷 게이트웨이 등을 제공한다.
  - 주로 L3 네트워크 설계와 관련된다.

- **Security Group**
  - 인스턴스 또는 ENI에 적용되는 상태 저장 방화벽이다.
  - TCP/UDP 포트, 프로토콜, 출발지/목적지 기준으로 제어한다.
  - 주로 L3/L4 제어에 해당한다.

- **Network ACL**
  - 서브넷 단위의 상태 비저장 방화벽이다.
  - 인바운드와 아웃바운드 규칙을 별도로 평가한다.

- **Elastic Load Balancing**
  - Network Load Balancer는 주로 L4 로드 밸런싱에 사용된다.
  - Application Load Balancer는 HTTP/HTTPS 기반 L7 로드 밸런싱에 사용된다.

## GCP

GCP에서도 유사한 개념이 존재한다.

- **VPC Network**
  - 글로벌 논리 네트워크로 서브넷, 라우팅, 방화벽 규칙을 구성한다.
- **Cloud Load Balancing**
  - HTTP(S) Load Balancer는 L7 트래픽 처리를 제공한다.
  - TCP/UDP 기반 로드 밸런싱 서비스는 L4 성격을 가진다.
- **Firewall Rules**
  - 인스턴스 네트워크 태그, 서비스 계정, IP 범위, 프로토콜/포트 등을 기준으로 트래픽을 제어한다.

실무에서 장애를 분석할 때는 다음과 같이 계층별로 점검한다.

```text
L1/L2: NIC 상태, 링크 업 여부, MAC, VLAN
L3: IP 주소, 라우팅 테이블, 게이트웨이, ICMP
L4: 포트 리스닝, TCP handshake, 방화벽
L5~L7: TLS 인증서, HTTP 상태 코드, 애플리케이션 로그
```

## 클라우드 연결

클라우드 환경에서는 물리 장비를 직접 다루지 않더라도 OSI/TCP-IP 계층 개념이 매우 중요하다. 클라우드 네트워크는 가상화된 NIC, 가상 라우터, 소프트웨어 정의 네트워크, 로드 밸런서, 방화벽 정책 위에서 동작하기 때문이다.

## Docker

Docker 컨테이너는 기본적으로 격리된 네트워크 네임스페이스를 가진다. 컨테이너 내부에서 보면 독립적인 네트워크 인터페이스와 IP 주소가 있는 것처럼 보인다.

대표적인 Docker 네트워크 모드는 다음과 같다.

- **bridge**
  - 기본 네트워크 모드이다.
  - 호스트의 가상 브리지와 컨테이너의 veth pair를 통해 통신한다.
  - L2/L3 개념이 함께 사용된다.

- **host**
  - 컨테이너가 호스트의 네트워크 네임스페이스를 공유한다.
  - 별도의 포트 매핑 없이 호스트 네트워크를 직접 사용한다.

- **none**
  - 네트워크 인터페이스를 거의 제공하지 않는 격리 모드이다.

예를 들어 다음 명령은 컨테이너의 80 포트를 호스트의 8080 포트로 매핑한다.

```bash
docker run -p 8080:80 nginx
```

이 경우 외부 클라이언트는 `호스트IP:8080`으로 접속하고, Docker는 NAT 또는 프록시 동작을 통해 컨테이너의 80 포트로 전달한다. 이는 L3/L4 주소와 포트 변환을 이해해야 정확히 설명할 수 있다.

## Kubernetes

Kubernetes는 컨테이너 네트워크를 추상화한다. 기본 원칙은 Pod가 고유한 IP를 가지고, Pod 간 통신이 NAT 없이 가능하도록 설계되는 것이다.

주요 구성 요소는 다음과 같다.

- **Pod 네트워크**
  - 각 Pod는 IP 주소를 가진다.
  - CNI(Container Network Interface) 플러그인이 네트워크 연결을 구성한다.

- **Service**
  - Pod 집합에 안정적인 가상 IP와 DNS 이름을 제공한다.
  - ClusterIP, NodePort, LoadBalancer 등이 있다.
  - 주로 L4 로드 밸런싱에 해당한다.

- **Ingress**
  - HTTP/HTTPS 요청을 경로 또는 호스트명 기준으로 라우팅한다.
  - L7 라우팅 개념이다.

- **NetworkPolicy**
  - Pod 간 통신을 제어하는 정책이다.
  - 구현 여부와 동작은 사용하는 CNI 플러그인에 의존한다.

Kubernetes 요청 흐름 예시는 다음과 같다.

```text
Client
 → Cloud Load Balancer
 → Ingress Controller
 → Kubernetes Service
 → Pod
 → Container Application
```

이 흐름에서 Cloud Load Balancer는 L4 또는 L7일 수 있고, Ingress Controller는 일반적으로 L7 HTTP 라우팅을 담당하며, Service는 Pod로 트래픽을 분산한다.

## AWS 서비스와의 연관성

AWS에서 계층 모델을 적용하면 다음처럼 이해할 수 있다.

| 계층 관점 | AWS 예시 |
|---|---|
| L3 | VPC, Subnet, Route Table, Internet Gateway, NAT Gateway |
| L4 | Security Group, NLB, TCP/UDP 포트 제어 |
| L7 | ALB, API Gateway, CloudFront, WAF |

예를 들어 사용자가 AWS에서 운영 중인 웹 애플리케이션에 접속하는 경로는 다음과 같다.

```text
사용자 브라우저
 → DNS Route 53
 → CloudFront
 → AWS WAF
 → Application Load Balancer
 → EC2 또는 ECS/EKS 서비스
 → 애플리케이션 컨테이너
```

이때 Route 53은 DNS, CloudFront는 CDN, WAF는 L7 보안 필터링, ALB는 L7 로드 밸런싱, Security Group은 L3/L4 접근 제어 역할을 한다.

## 보안 연결

네트워크 계층 모델은 보안 설계와 침해 대응에서 핵심적인 분석 기준이 된다. 공격자는 특정 계층을 노려 통신을 가로채거나, 서비스를 마비시키거나, 인증을 우회하려고 한다. 방어자는 계층별로 적절한 통제 수단을 배치해야 한다.

## 계층별 보안 이슈

| 계층 | 주요 보안 이슈 | 방어 방법 |
|---|---|---|
| L1 물리 | 케이블 도청, 장비 탈취 | 물리 접근 통제, 포트 보안 |
| L2 데이터 링크 | ARP 스푸핑, MAC 플러딩, VLAN hopping | 스위치 보안, DHCP Snooping, Dynamic ARP Inspection |
| L3 네트워크 | IP 스푸핑, 라우팅 공격, ICMP 악용 | 라우팅 필터링, ACL, Anti-spoofing |
| L4 전송 | SYN Flood, 포트 스캔, UDP Flood | 방화벽, SYN Cookies, Rate Limiting |
| L5~L7 응용 | SQL Injection, XSS, HTTP Flood, 인증 우회 | WAF, 입력 검증, 인증 강화, 보안 헤더 |

## TCP/IP 관점의 주요 보안 포인트

### 1. IP 계층 보안

IP는 기본적으로 패킷 전달을 담당하며, 자체적으로 송신자의 신원을 강하게 검증하지 않는다. 따라서 IP 스푸핑 같은 공격이 가능하다. 이를 완화하기 위해 네트워크 경계에서 비정상 출발지 IP를 차단하고, 클라우드 환경에서는 Security Group, Network ACL, 라우팅 정책을 적절히 구성해야 한다.

### 2. TCP 계층 보안

TCP는 연결 수립 과정에서 3-way handshake를 사용한다. 공격자는 다량의 SYN 패킷을 보내 서버의 연결 대기 자원을 고갈시키는 SYN Flood 공격을 시도할 수 있다. 이를 방어하기 위해 운영체제의 SYN Cookies, 로드 밸런서, DDoS 방어 서비스, 연결 제한 정책을 사용할 수 있다.

### 3. DNS 보안

DNS는 응용 계층 프로토콜이지만 네트워크 전체의 시작점인 경우가 많다. DNS 스푸핑, 캐시 포이즈닝, 도메인 하이재킹은 사용자를 악성 서버로 유도할 수 있다. DNSSEC, 신뢰할 수 있는 DNS 리졸버 사용, 도메인 계정 보호, 레지스트리 잠금 등이 방어 수단이 될 수 있다.

### 4. TLS 보안

HTTPS는 HTTP에 TLS를 결합한 형태이다. TLS는 데이터 기밀성, 무결성, 서버 인증을 제공한다. 하지만 인증서 만료, 약한 암호군 사용, 잘못된 인증서 검증 로직은 보안 취약점이 될 수 있다. 서버는 최신 TLS 설정, 안전한 cipher suite, HSTS, 인증서 자동 갱신 체계를 갖추는 것이 좋다.

### 5. L7 보안

HTTP 계층에서는 URL, 헤더, 쿠키, 본문 등 애플리케이션 데이터가 공격 대상이 된다. SQL Injection, XSS, CSRF, SSRF 같은 공격은 대부분 L7에서 발생한다. 방어를 위해 입력 검증, 출력 인코딩, 인증/인가 검증, WAF, 보안 로깅이 필요하다.

## 모범 사례

- 최소 권한 원칙에 따라 필요한 포트만 개방한다.
- 인터넷에 직접 노출되는 서비스는 로드 밸런서, WAF, CDN 뒤에 배치한다.
- 관리용 포트 SSH, RDP 등은 접근 IP를 제한한다.
- 내부망과 외부망을 서브넷, 라우팅, 방화벽 정책으로 분리한다.
- TLS 인증서를 주기적으로 관리하고 만료를 모니터링한다.
- 네트워크 로그, VPC Flow Logs, 방화벽 로그, 웹 서버 로그를 수집한다.
- L3/L4 방화벽과 L7 WAF를 함께 사용해 다층 방어를 구성한다.
- Kubernetes에서는 NetworkPolicy를 사용해 Pod 간 통신을 제한한다.
- 컨테이너 환경에서는 불필요한 포트 노출을 피하고, 호스트 네트워크 모드 사용을 신중히 결정한다.

## 면접 질문

**Q1. OSI 7계층과 TCP/IP 4계층의 차이는 무엇인가요?**  
> 핵심 답변: OSI 7계층은 네트워크 통신 기능을 7개 계층으로 세분화한 참조 모델이고, TCP/IP 4계층은 실제 인터넷 프로토콜 스택에 기반한 모델이다. OSI의 응용·표현·세션 계층은 TCP/IP의 응용 계층에 대응되고, OSI의 데이터 링크·물리 계층은 TCP/IP의 네트워크 액세스 계층에 대응된다.

**Q2. TCP와 UDP의 차이는 무엇인가요?**  
> 핵심 답변: TCP는 연결 지향형이며 신뢰성, 순서 보장, 흐름 제어, 혼잡 제어를 제공한다. UDP는 비연결형이며 신뢰성 보장을 하지 않지만 오버헤드가 적고 지연이 낮다. TCP는 HTTP/1.1, HTTP/2, SSH 등에 사용되고, UDP는 DNS, 실시간 스트리밍, VoIP, QUIC 등에 사용된다.

**Q3. L4 로드 밸런서와 L7 로드 밸런서의 차이는 무엇인가요?**  
> 핵심 답변: L4 로드 밸런서는 IP와 포트, TCP/UDP 연결 정보를 기준으로 트래픽을 분산한다. L7 로드 밸런서는 HTTP 헤더, URI, Host, Cookie 같은 애플리케이션 데이터를 기준으로 라우팅할 수 있다. AWS NLB는 대표적인 L4 로드 밸런서이고, AWS ALB는 대표적인 L7 로드 밸런서이다.

**Q4. 사용자가 브라우저에 URL을 입력했을 때 네트워크 계층별로 어떤 일이 발생하나요?**  
> 핵심 답변: 먼저 DNS로 도메인을 IP 주소로 변환한다. 이후 라우팅을 통해 목적지 서버로 패킷이 전달된다. TCP 연결이 필요한 경우 3-way handshake가 수행되고, HTTPS라면 TLS 핸드셰이크가 이어진다. 그 후 HTTP 요청이 서버로 전달되고, 서버는 HTTP 응답을 반환한다. 이 과정에서 데이터는 응용 계층에서 물리 계층으로 캡슐화되고, 수신 측에서 역캡슐화된다.

**Q5. ARP는 어떤 계층에서 동작하며 왜 필요한가요?**  
> 핵심 답변: ARP는 IPv4 주소를 같은 로컬 네트워크 내의 MAC 주소로 변환하기 위해 사용된다. OSI 관점에서는 데이터 링크 계층과 네트워크 계층 사이의 역할을 한다고 설명할 수 있다. IP 패킷을 실제 Ethernet 프레임으로 보내려면 목적지 MAC 주소가 필요하기 때문에 ARP가 필요하다.

## 관련 개념

- [[TCP]] - 신뢰성 있는 연결 지향 전송 계층 프로토콜로 OSI 4계층 이해의 핵심이다.
- [[UDP]] - 비연결형 전송 프로토콜로 DNS, QUIC, 실시간 통신 이해에 필요하다.
- [[IP Address]] - 네트워크 계층에서 라우팅과 호스트 식별에 사용되는 주소 개념이다.
- [[DNS]] - 도메인 이름을 IP 주소로 변환하는 응용 계층 핵심 프로토콜이다.
- [[HTTP]] - 웹 통신의 대표적인 응용 계층 프로토콜이다.
- [[TLS]] - HTTPS에서 암호화와 인증을 제공하며 표현 계층 또는 응용 계층 보안과 관련된다.
- [[ARP]] - IPv4 주소를 MAC 주소로 매핑하여 로컬 네트워크 통신을 가능하게 한다.
- [[라우팅]] - 네트워크 계층에서 목적지까지 패킷 경로를 결정하는 과정이다.
- [[NAT]] - 사설 IP와 공인 IP 간 주소 변환으로 클라우드와 Docker 네트워크에서 자주 사용된다.
- [[로드 밸런서]] - L4 또는 L7에서 트래픽을 여러 서버로 분산하는 핵심 인프라 구성 요소다.
- [[방화벽]] - 네트워크 계층과 전송 계층 또는 응용 계층에서 트래픽을 제어하는 보안 장치다.
- [[Kubernetes Service]] - Pod 집합에 안정적인 접근 지점을 제공하며 L4 로드 밸런싱 개념과 연결된다.
- [[Ingress Controller]] - Kubernetes에서 HTTP/HTTPS 기반 L7 라우팅을 담당한다.
