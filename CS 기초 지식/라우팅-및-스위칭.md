# 라우팅 및 스위칭 - L2 스위치 vs L3 라우터, NAT, Port Forwarding

## 핵심 개념

라우팅과 스위칭은 네트워크에서 패킷 또는 프레임을 목적지까지 전달하기 위한 핵심 기술이다. **L2 스위치**는 OSI 2계층인 데이터링크 계층에서 동작하며, 주로 **MAC 주소**를 기준으로 이더넷 프레임을 전달한다. 같은 LAN 또는 같은 VLAN 내부에서 장비 간 통신을 효율적으로 처리하는 것이 목적이다. 반면 **L3 라우터**는 OSI 3계층인 네트워크 계층에서 동작하며, **IP 주소**와 라우팅 테이블을 기준으로 서로 다른 네트워크 간 패킷을 전달한다.

예를 들어 같은 사무실 LAN 안에서 PC A가 PC B로 데이터를 보낼 때는 L2 스위치가 MAC 주소를 보고 프레임을 전달한다. 하지만 사무실 내부 PC가 인터넷 서버에 접속하려면 내부 네트워크와 외부 인터넷 사이를 연결하는 라우터가 필요하다.

**NAT(Network Address Translation)**는 라우터나 방화벽 장비가 IP 패킷의 출발지 또는 목적지 IP 주소를 변환하는 기술이다. 가장 흔한 목적은 사설 IP 주소를 사용하는 내부 네트워크 장비들이 공인 IP 주소 하나 또는 일부를 공유해 인터넷에 접속하도록 하는 것이다. IPv4 주소 부족 문제를 완화하는 데 매우 중요한 역할을 해왔다.

**Port Forwarding**은 NAT의 한 형태로, 외부에서 특정 공인 IP와 포트로 들어온 요청을 내부 네트워크의 특정 사설 IP와 포트로 전달하는 방식이다. 예를 들어 외부 사용자가 `203.0.113.10:80`으로 접속하면 라우터가 이를 내부 서버 `192.168.0.10:80`으로 전달할 수 있다.

이 개념들이 중요한 이유는 대부분의 실제 네트워크, 가정용 공유기, 기업망, 클라우드 VPC, 컨테이너 네트워크, Kubernetes 서비스 네트워킹이 모두 스위칭, 라우팅, NAT, 포트 매핑 개념 위에서 동작하기 때문이다. 이를 이해하지 못하면 서버 접속 장애, 방화벽 문제, 포트 충돌, 클라우드 네트워크 설계, 보안 그룹 설정 등을 정확히 진단하기 어렵다.

## 내부 동작 원리

## 1. L2 스위치의 동작 원리

L2 스위치는 이더넷 프레임의 **출발지 MAC 주소**를 보고 MAC 주소 테이블을 학습하고, **목적지 MAC 주소**를 보고 어느 포트로 프레임을 내보낼지 결정한다.

### L2 스위치 기본 흐름

```text
PC A
MAC: AA:AA
IP : 192.168.1.10
   |
   | Ethernet Frame
   v
+------------------+
|    L2 Switch     |
| MAC Table        |
| AA:AA -> Port 1  |
| BB:BB -> Port 2  |
+------------------+
   |
   v
PC B
MAC: BB:BB
IP : 192.168.1.20
```

### 동작 과정

1. PC A가 PC B에게 데이터를 보내기 위해 이더넷 프레임을 생성한다.
2. 프레임에는 출발지 MAC 주소 `AA:AA`, 목적지 MAC 주소 `BB:BB`가 포함된다.
3. 스위치는 프레임을 수신한 포트를 보고 `AA:AA`가 어느 포트에 있는지 MAC 주소 테이블에 학습한다.
4. 목적지 MAC 주소 `BB:BB`가 MAC 주소 테이블에 있으면 해당 포트로만 전달한다.
5. 목적지 MAC 주소를 모르면 같은 VLAN 내 다른 포트로 플러딩한다.
6. 브로드캐스트 프레임도 같은 VLAN 내 모든 관련 포트로 전달된다.

### 핵심 특징

- MAC 주소 기반 전달
- 같은 VLAN 내부 통신 담당
- 기본적으로 IP 주소를 보지 않음
- 브로드캐스트 도메인 단위로 동작
- VLAN을 사용하면 하나의 물리 스위치에서 여러 논리 네트워크를 분리할 수 있음

---

## 2. L3 라우터의 동작 원리

L3 라우터는 IP 패킷의 **목적지 IP 주소**를 보고 라우팅 테이블에서 다음 홉 또는 출력 인터페이스를 결정한다.

```text
192.168.1.0/24              10.0.0.0/24
+---------+                 +---------+
|  PC A   |                 | Server  |
| .1.10   |                 | .0.20   |
+----+----+                 +----+----+
     |                           |
     v                           ^
+--------------------------------------+
|              Router                  |
| eth0: 192.168.1.1                   |
| eth1: 10.0.0.1                      |
| Routing Table                       |
| 192.168.1.0/24 -> eth0              |
| 10.0.0.0/24    -> eth1              |
| 0.0.0.0/0      -> ISP Gateway       |
+--------------------------------------+
```

### 동작 과정

1. PC A가 다른 네트워크 `10.0.0.20`으로 패킷을 보내려 한다.
2. PC A는 목적지가 자신의 서브넷이 아님을 판단한다.
3. PC A는 기본 게이트웨이인 라우터 `192.168.1.1`로 패킷을 보낸다.
4. 이때 이더넷 프레임의 목적지 MAC 주소는 라우터 인터페이스의 MAC 주소가 된다.
5. 라우터는 프레임을 벗겨 IP 패킷을 확인한다.
6. 목적지 IP `10.0.0.20`을 라우팅 테이블과 비교한다.
7. 가장 긴 프리픽스 매치, 즉 Longest Prefix Match 규칙에 따라 적절한 경로를 선택한다.
8. 라우터는 TTL 값을 감소시키고, 필요하면 체크섬을 갱신한 뒤 다음 네트워크로 패킷을 전달한다.
9. 새 이더넷 프레임을 만들어 다음 홉의 MAC 주소로 전송한다.

### L2 스위치와 L3 라우터 비교

| 구분 | L2 스위치 | L3 라우터 |
|---|---|---|
| 기준 주소 | MAC 주소 | IP 주소 |
| 동작 계층 | 데이터링크 계층 | 네트워크 계층 |
| 주요 단위 | 프레임 | 패킷 |
| 주요 역할 | 같은 네트워크 내부 전달 | 서로 다른 네트워크 간 전달 |
| 테이블 | MAC 주소 테이블 | 라우팅 테이블 |
| 브로드캐스트 | 같은 VLAN 내 전달 | 기본적으로 브로드캐스트 차단 |
| 대표 기능 | 스위칭, VLAN | 라우팅, NAT, ACL |

## 3. NAT 동작 원리

NAT는 패킷의 IP 주소 또는 포트 번호를 변환한다. 가장 일반적인 형태는 **SNAT(Source NAT)** 또는 **PAT/Overload NAT**이다. PAT는 여러 내부 호스트가 하나의 공인 IP를 공유할 수 있게 출발지 포트까지 함께 변환한다.

```text
내부 PC
192.168.0.10:51512
      |
      | 요청
      v
+-------------------------------+
| NAT Router                    |
| 내부: 192.168.0.1             |
| 외부: 203.0.113.10            |
| NAT Table                     |
| 192.168.0.10:51512            |
| -> 203.0.113.10:40001         |
+-------------------------------+
      |
      v
인터넷 서버
198.51.100.20:443
```

### 내부에서 외부로 나가는 NAT 과정

1. 내부 PC `192.168.0.10:51512`가 외부 서버 `198.51.100.20:443`에 접속한다.
2. 라우터는 출발지 IP가 사설 IP임을 확인한다.
3. 출발지 IP와 포트를 `203.0.113.10:40001` 같은 공인 IP와 포트로 변환한다.
4. NAT 테이블에 다음과 같은 매핑을 저장한다.

```text
192.168.0.10:51512 <-> 203.0.113.10:40001
```

5. 외부 서버는 응답을 `203.0.113.10:40001`로 보낸다.
6. NAT 라우터는 NAT 테이블을 조회해 원래 내부 주소 `192.168.0.10:51512`로 되돌려 전달한다.

### NAT의 주요 종류

| 종류 | 설명 |
|---|---|
| SNAT | 출발지 IP 주소 변환 |
| DNAT | 목적지 IP 주소 변환 |
| PAT | IP뿐 아니라 포트까지 변환하여 다수의 내부 호스트가 하나의 공인 IP를 공유 |
| Static NAT | 특정 내부 IP와 외부 IP를 고정 매핑 |
| Dynamic NAT | 외부 IP 풀에서 동적으로 매핑 |

## 4. Port Forwarding 동작 원리

Port Forwarding은 외부에서 내부 서버로 접근할 수 있도록 NAT 장비가 특정 포트 요청을 내부 IP와 포트로 전달하는 방식이다. 기술적으로는 DNAT와 관련이 깊다.

```text
외부 클라이언트
1.2.3.4:53000
      |
      | 접속: 203.0.113.10:8080
      v
+-------------------------------+
| NAT Router                    |
| Port Forward Rule             |
| 203.0.113.10:8080             |
| -> 192.168.0.50:80            |
+-------------------------------+
      |
      v
내부 웹 서버
192.168.0.50:80
```

### 동작 과정

1. 외부 클라이언트가 `203.0.113.10:8080`으로 접속한다.
2. NAT 라우터는 포트 포워딩 규칙을 확인한다.
3. 목적지 주소를 `192.168.0.50:80`으로 변경한다.
4. 내부 서버는 요청을 받고 응답한다.
5. 라우터는 응답 패킷의 출발지 주소를 다시 `203.0.113.10:8080`으로 변환해 외부 클라이언트에게 전달한다.

### 주의할 점

- 내부 서버의 사설 IP가 바뀌면 포워딩 규칙이 깨질 수 있다.
- 외부에 포트를 개방하므로 보안 위험이 증가한다.
- 방화벽 정책과 NAT 정책이 함께 맞아야 정상 동작한다.
- 동일한 외부 IP와 포트는 일반적으로 하나의 내부 목적지로만 매핑할 수 있다.

## 실제 시스템 연결

## 1. Linux에서 라우팅 확인

Linux에서는 `ip route` 명령으로 라우팅 테이블을 확인할 수 있다.

```bash
ip route
```

예시:

```text
default via 192.168.0.1 dev eth0
192.168.0.0/24 dev eth0 proto kernel scope link src 192.168.0.10
```

의미:

- `default via 192.168.0.1`: 목적지 경로를 모르면 기본 게이트웨이로 전달
- `192.168.0.0/24 dev eth0`: 같은 서브넷은 eth0으로 직접 전달
- `src 192.168.0.10`: 해당 경로를 사용할 때 기본 출발지 IP

라우팅 추가 예시:

```bash
sudo ip route add 10.0.0.0/24 via 192.168.0.254
```

이 명령은 `10.0.0.0/24` 네트워크로 가는 패킷을 `192.168.0.254` 게이트웨이로 보내도록 설정한다.

---

## 2. Linux에서 NAT 설정

Linux에서는 일반적으로 `iptables` 또는 `nftables`를 사용해 NAT를 설정할 수 있다. 최근 Linux 배포판에서는 `nftables`가 기본 방화벽 프레임워크로 사용되는 경우가 많지만, 배포판과 버전에 따라 다르다.

### iptables MASQUERADE 예시

```bash
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```

의미:

- `-t nat`: NAT 테이블 사용
- `POSTROUTING`: 라우팅 결정 이후, 패킷이 나가기 직전에 적용
- `-o eth0`: eth0으로 나가는 패킷 대상
- `MASQUERADE`: 나가는 인터페이스의 IP로 출발지 주소 변환

IP 포워딩도 활성화해야 라우터처럼 동작할 수 있다.

```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

영구 설정은 일반적으로 `/etc/sysctl.conf` 또는 `/etc/sysctl.d/` 아래 설정 파일을 사용한다.

---

## 3. Linux에서 Port Forwarding 설정

예를 들어 외부에서 `8080` 포트로 들어온 요청을 내부 서버 `192.168.0.50:80`으로 전달하려면 다음과 같은 형태의 DNAT 규칙을 사용할 수 있다.

```bash
sudo iptables -t nat -A PREROUTING -p tcp --dport 8080 \
  -j DNAT --to-destination 192.168.0.50:80
```

또한 응답 경로가 NAT 장비를 통해 돌아오도록 SNAT 또는 MASQUERADE 설정이 필요할 수 있다.

```bash
sudo iptables -t nat -A POSTROUTING -j MASQUERADE
```

실제 환경에서는 인터페이스, 서브넷, 방화벽 정책, 커널 포워딩 설정을 함께 확인해야 한다.

## 4. Nginx와 Port Forwarding의 차이

Nginx 리버스 프록시는 애플리케이션 계층에 가까운 방식으로 요청을 받아 백엔드 서버로 전달한다. 반면 Port Forwarding은 네트워크 계층 또는 전송 계층 수준에서 주소와 포트를 변환한다.

```text
Port Forwarding:
Client -> PublicIP:8080 -> NAT -> 192.168.0.50:80

Nginx Reverse Proxy:
Client -> Nginx:443 -> HTTP Host/Header 기반 -> Backend Server
```

차이점:

| 구분 | Port Forwarding | Nginx Reverse Proxy |
|---|---|---|
| 주요 계층 | L3/L4 | L7 |
| 기준 | IP, 포트 | HTTP Host, Path, Header 등 |
| TLS 종료 | 일반적으로 하지 않음 | 가능 |
| 로드밸런싱 | 제한적 | 가능 |
| 인증/캐싱 | 직접 제공하지 않음 | 설정 가능 |

## 5. 가정용 공유기 사례

가정용 공유기는 일반적으로 다음 기능을 동시에 수행한다.

- L2 스위치: LAN 포트 간 이더넷 프레임 전달
- L3 라우터: 내부망과 인터넷망 사이 IP 패킷 전달
- NAT: 사설 IP를 공인 IP로 변환
- DHCP 서버: 내부 장비에 사설 IP 자동 할당
- 방화벽: 외부에서 내부로 들어오는 불필요한 연결 차단
- Port Forwarding: 특정 내부 장비로 외부 접속 전달

즉, 사용자는 하나의 공유기를 사용하지만 내부적으로는 스위치, 라우터, NAT 게이트웨이, 방화벽, DHCP 서버가 결합된 형태로 동작한다.

## 클라우드 연결

## 1. Docker와 NAT

Docker의 기본 브리지 네트워크는 컨테이너에 사설 IP 대역을 할당하고, 호스트의 NAT 기능을 통해 외부 네트워크와 통신하게 한다.

```text
Container
172.17.0.2:80
    |
    v
docker0 bridge
172.17.0.1
    |
    v
Host NAT
    |
    v
External Network
```

컨테이너 실행 예시:

```bash
docker run -p 8080:80 nginx
```

이 명령은 호스트의 `8080` 포트로 들어온 요청을 컨테이너의 `80` 포트로 전달한다. 개념적으로 Port Forwarding과 유사하다.

```text
Client -> HostIP:8080 -> ContainerIP:80
```

확인 명령:

```bash
docker ps
docker port <container_id>
```

Docker는 Linux 환경에서 iptables 또는 nftables 기반 규칙을 활용할 수 있다. 구체적인 구현은 Docker 버전, 운영체제, 네트워크 드라이버 설정에 따라 달라질 수 있다.

## 2. Kubernetes Service와 Port Forwarding

Kubernetes에서는 Pod IP가 동적으로 변할 수 있으므로, 직접 Pod IP로 접근하는 대신 Service를 사용한다.

```text
Client
  |
  v
Service IP:Port
  |
  v
Pod A / Pod B / Pod C
```

Service의 주요 유형:

| 유형 | 설명 |
|---|---|
| ClusterIP | 클러스터 내부에서만 접근 가능한 가상 IP 제공 |
| NodePort | 각 노드의 특정 포트를 통해 Service 접근 |
| LoadBalancer | 클라우드 로드밸런서를 생성해 외부 접근 제공 |
| ExternalName | DNS 이름으로 외부 서비스를 참조 |

`kubectl port-forward`는 로컬 포트를 Pod 또는 Service 포트로 터널링하는 개발·디버깅용 기능이다.

```bash
kubectl port-forward pod/my-pod 8080:80
```

의미:

```text
localhost:8080 -> my-pod:80
```

이는 네트워크 장비의 Port Forwarding과 이름은 같지만, Kubernetes API 서버와 kubectl을 통해 연결을 중계하는 개발 편의 기능으로 이해하는 것이 좋다.

## 3. AWS VPC에서 라우팅

AWS VPC는 사용자가 정의한 가상 네트워크이다. VPC 내부에는 서브넷, 라우팅 테이블, 인터넷 게이트웨이, NAT 게이트웨이 등이 있다.

```text
Public Subnet
EC2 Public
   |
   v
Internet Gateway
   |
 Internet

Private Subnet
EC2 Private
   |
   v
NAT Gateway
   |
   v
Internet Gateway
   |
 Internet
```

### 주요 구성요소

- **Route Table**: 서브넷의 트래픽이 어디로 갈지 결정
- **Internet Gateway**: VPC와 인터넷 간 통신 경로 제공
- **NAT Gateway**: 프라이빗 서브넷의 인스턴스가 인터넷으로 나갈 수 있게 함
- **Security Group**: 인스턴스 단위의 상태 저장 방화벽
- **Network ACL**: 서브넷 단위의 상태 비저장 방화벽

예시 라우팅:

```text
Public Subnet Route Table
10.0.0.0/16 -> local
0.0.0.0/0  -> Internet Gateway

Private Subnet Route Table
10.0.0.0/16 -> local
0.0.0.0/0  -> NAT Gateway
```

프라이빗 서브넷의 서버는 NAT Gateway를 통해 외부 패키지 저장소에 접근할 수 있지만, 외부 인터넷에서 해당 서버로 직접 연결되지는 않는다.

## 4. AWS Port Forwarding 관련 사례

AWS에서 전통적인 공유기식 포트 포워딩은 보통 다음 방식들로 대체된다.

- EC2 퍼블릭 IP와 Security Group 인바운드 규칙
- Application Load Balancer를 통한 HTTP/HTTPS 라우팅
- Network Load Balancer를 통한 TCP/UDP 전달
- Systems Manager Session Manager를 통한 포트 터널링
- Bastion Host를 통한 SSH 터널링

예를 들어 외부에서 내부 EC2의 웹 애플리케이션에 접근하게 하려면 일반적으로 다음 구조를 사용한다.

```text
Client
  |
  v
Application Load Balancer : 443
  |
  v
Private Subnet EC2 : 8080
```

이때 Security Group은 다음처럼 설계할 수 있다.

- ALB: 인터넷에서 `443` 허용
- EC2: ALB의 Security Group에서 오는 `8080`만 허용

이 방식은 단순 포트 포워딩보다 보안 정책, 인증서 관리, 로드밸런싱, 헬스 체크 측면에서 유리하다.

## 5. GCP와 Cloud NAT

GCP에서도 VPC, 서브넷, 라우팅, 방화벽 규칙, Cloud NAT를 사용해 유사한 구조를 만든다. Cloud NAT는 외부 IP가 없는 VM이 인터넷으로 나가는 아웃바운드 연결을 할 수 있도록 지원한다.

```text
Private VM
   |
   v
Cloud NAT
   |
   v
Internet
```

Cloud NAT는 기본적으로 외부에서 내부 VM으로 들어오는 인바운드 연결을 허용하기 위한 서비스가 아니다. 외부 접근이 필요하면 Load Balancer, 외부 IP, IAP TCP forwarding 등의 방식을 고려한다.

## 보안 연결

## 1. L2 스위칭 보안 이슈

L2 네트워크에서는 같은 브로드캐스트 도메인 안의 장비들이 서로 ARP, DHCP, 브로드캐스트 트래픽의 영향을 받을 수 있다.

대표적인 공격 또는 위험:

- **MAC Flooding**: 스위치의 MAC 주소 테이블을 가득 채워 허브처럼 플러딩하게 유도
- **ARP Spoofing / ARP Poisoning**: 공격자가 게이트웨이의 MAC 주소를 위조해 중간자 공격 수행
- **VLAN Hopping**: 잘못된 트렁크 설정 등을 악용해 다른 VLAN 트래픽에 접근 시도
- **Rogue DHCP Server**: 공격자가 가짜 DHCP 서버를 운영해 잘못된 게이트웨이/DNS 제공

모범 사례:

- 포트 보안 기능 사용
- 사용하지 않는 포트 비활성화
- VLAN 분리
- DHCP Snooping, Dynamic ARP Inspection 같은 스위치 보안 기능 사용
- 관리 VLAN과 사용자 VLAN 분리
- 스위치 관리 인터페이스 접근 제한

---

## 2. L3 라우팅 보안 이슈

라우터는 네트워크 간 경계에 위치하므로 잘못된 라우팅 설정은 트래픽 우회, 접근 제어 우회, 장애 확산으로 이어질 수 있다.

주요 위험:

- 잘못된 기본 라우트로 인한 트래픽 유출
- 라우팅 루프
- 비인가 네트워크 간 통신 허용
- 라우팅 프로토콜 인증 미설정으로 인한 경로 주입 위험
- 관리 인터페이스 노출

모범 사례:

- 최소 권한 기반 라우팅과 ACL 적용
- 관리용 인터페이스를 별도 네트워크로 분리
- 라우팅 프로토콜 사용 시 인증과 필터링 적용
- 불필요한 ICMP, 관리 포트 노출 제한
- 라우팅 변경에 대한 모니터링과 감사 로그 유지

---

## 3. NAT의 보안적 의미와 한계

NAT는 내부 사설 IP를 외부에 직접 노출하지 않기 때문에 일정 수준의 은닉 효과를 제공한다. 그러나 NAT 자체가 완전한 보안 장치는 아니다. 보안은 방화벽 정책, 접근 제어, 패치 관리, 인증, 로깅과 함께 설계되어야 한다.

### NAT가 제공하는 효과

- 내부 사설 IP 주소 은닉
- 외부에서 임의로 내부 호스트에 직접 접근하기 어려움
- 상태 기반 NAT에서는 내부에서 시작한 연결의 응답만 허용되는 경우가 많음

### NAT의 한계

- 내부 사용자가 악성 서버로 접속하는 것은 막지 못함
- 포트 포워딩을 열면 내부 서비스가 외부에 노출됨
- NAT 장비 자체가 침해되면 내부망 접근 위험 증가
- 로그가 없으면 내부의 어떤 호스트가 외부와 통신했는지 추적하기 어려움
- 일부 프로토콜은 주소 정보를 페이로드에 포함하므로 NAT 통과 문제가 발생할 수 있음

---

## 4. Port Forwarding 보안 이슈

Port Forwarding은 외부 인터넷에서 내부 서비스로 들어오는 경로를 직접 만든다. 따라서 잘못 설정하면 내부 서버가 공격 표면에 노출된다.

위험 사례:

```text
0.0.0.0:22 -> 192.168.0.10:22
```

이렇게 SSH를 전 세계에 개방하면 무차별 대입 공격, 취약한 계정 공격, 오래된 SSH 서버 취약점 공격을 받을 수 있다.

모범 사례:

- 꼭 필요한 포트만 개방
- 가능하면 VPN 또는 Zero Trust 접근 방식 사용
- SSH는 공개키 인증 사용, 비밀번호 로그인 비활성화 고려
- 관리자 포트는 특정 IP에서만 접근 허용
- 기본 포트 변경은 보안의 핵심 대책은 아니지만 자동화된 스캔 노이즈를 줄이는 보조 수단이 될 수 있음
- 서비스별 인증, TLS, 최신 패치 적용
- 외부 노출 포트 주기적 점검
- 로그 모니터링 및 침입 탐지 적용

---

## 5. 클라우드 환경의 보안 모범 사례

클라우드에서는 NAT, 라우팅, 방화벽 역할이 여러 서비스로 분산된다. 예를 들어 AWS에서는 Route Table, Security Group, NACL, NAT Gateway, Load Balancer가 각각 다른 역할을 한다.

모범 사례:

- 퍼블릭 서브넷과 프라이빗 서브넷 분리
- 애플리케이션 서버는 가능하면 프라이빗 서브넷에 배치
- 외부 접근은 Load Balancer를 통해 제한적으로 허용
- Security Group은 필요한 소스와 포트만 허용
- `0.0.0.0/0` 인바운드 허용은 반드시 검토
- NAT Gateway는 아웃바운드 인터넷 접근 용도로 사용
- 관리 접근은 Bastion Host, VPN, Session Manager, IAP 등을 사용
- VPC Flow Logs 같은 네트워크 로그 활성화
- IaC로 네트워크 정책을 코드화하고 변경 이력을 관리

## 면접 질문

**Q1. L2 스위치와 L3 라우터의 가장 큰 차이는 무엇인가요?**  
> 핵심 답변: L2 스위치는 MAC 주소를 기준으로 같은 네트워크 또는 같은 VLAN 내부에서 이더넷 프레임을 전달한다. L3 라우터는 IP 주소와 라우팅 테이블을 기준으로 서로 다른 네트워크 간 IP 패킷을 전달한다. 스위치는 MAC 주소 테이블을, 라우터는 라우팅 테이블을 사용한다.

**Q2. 스위치는 MAC 주소 테이블을 어떻게 학습하나요?**  
> 핵심 답변: 스위치는 수신한 프레임의 출발지 MAC 주소와 들어온 포트를 MAC 주소 테이블에 기록한다. 이후 목적지 MAC 주소가 테이블에 있으면 해당 포트로만 프레임을 전달하고, 없으면 같은 VLAN 내 포트들로 플러딩한다.

**Q3. NAT는 왜 필요한가요?**  
> 핵심 답변: NAT는 사설 IP를 사용하는 내부 호스트가 공인 IP를 통해 외부 인터넷과 통신할 수 있게 한다. 특히 PAT를 사용하면 여러 내부 호스트가 하나의 공인 IP를 공유할 수 있다. IPv4 주소 부족 완화, 내부 주소 은닉, 네트워크 주소 재구성 등에 활용된다.

**Q4. NAT와 Port Forwarding의 차이는 무엇인가요?**  
> 핵심 답변: NAT는 IP 주소 또는 포트를 변환하는 일반적인 기술이다. Port Forwarding은 외부의 특정 IP:포트로 들어온 연결을 내부의 특정 IP:포트로 전달하는 NAT/DNAT의 한 사용 방식이다. NAT는 주로 내부에서 외부로 나가는 통신에 많이 쓰이고, Port Forwarding은 외부에서 내부 서비스로 접근할 때 사용된다.

**Q5. AWS에서 프라이빗 서브넷의 EC2가 인터넷 패키지 저장소에 접근하려면 어떤 구성이 필요한가요?**  
> 핵심 답변: 프라이빗 서브넷의 라우팅 테이블에 `0.0.0.0/0` 경로를 NAT Gateway 또는 NAT Instance로 향하게 설정해야 한다. NAT Gateway는 퍼블릭 서브넷에 위치하고 Internet Gateway를 통해 인터넷에 연결된다. EC2의 Security Group과 NACL도 아웃바운드 및 응답 트래픽을 허용해야 한다.

- [[Security Group]] - AWS에서 인스턴스 또는 로드밸런서 단위로 적용되는 상태 저장 방화벽이다.
- [[Docker Network]] - 컨테이너 브리지 네트워크, NAT, 포트 매핑 개념과 직접적으로 연결된다.
- [[Kubernetes Service]] - Pod 집합에 안정적인 네트워크 접근 지점을 제공하며 가상 IP와 포트 전달 개념을 포함한다.
