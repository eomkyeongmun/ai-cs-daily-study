# 최단 경로 - 다익스트라, 플로이드-워셜, 벨만-포드

## 핵심 개념

최단 경로(Shortest Path)는 그래프에서 한 정점에서 다른 정점까지 이동할 때, 간선 가중치의 합이 최소가 되는 경로를 찾는 문제이다. 여기서 그래프의 정점은 서버, 라우터, 도시, 작업 상태 등을 의미할 수 있고, 간선은 네트워크 링크, 도로, 비용, 시간, 위험도 등을 나타낼 수 있다. 최단 경로 알고리즘은 네트워크 라우팅, 지도 경로 탐색, 물류 최적화, 게임 AI, 클라우드 네트워크 설계, 의존성 분석 등 다양한 시스템의 기반이 된다.

대표적인 최단 경로 알고리즘에는 **다익스트라(Dijkstra)**, **벨만-포드(Bellman-Ford)**, **플로이드-워셜(Floyd-Warshall)**이 있다. 다익스트라는 하나의 시작 정점에서 다른 모든 정점까지의 최단 경로를 구하는 알고리즘이며, **음수 가중치가 없는 그래프**에서 효율적이다. 벨만-포드는 역시 단일 시작점 최단 경로를 구하지만, **음수 가중치가 있는 그래프**에서도 동작하며 **음수 사이클 탐지**가 가능하다. 플로이드-워셜은 모든 정점 쌍 사이의 최단 경로를 구하는 알고리즘으로, 그래프의 크기가 비교적 작고 모든 쌍의 거리 정보가 필요한 경우에 적합하다.

이 세 알고리즘은 단순히 코딩 테스트용 지식에 그치지 않는다. 실제 네트워크 프로토콜, 클라우드 라우팅 구조, 서비스 간 호출 비용 분석, 보안 경로 분석 등에서 “어떤 경로가 가장 비용이 낮은가”를 판단하는 핵심 모델로 쓰인다. 따라서 각 알고리즘의 적용 조건, 시간 복잡도, 음수 간선 처리 여부, 음수 사이클 탐지 가능 여부를 정확히 이해하는 것이 중요하다.

요약하면 다음과 같다.

| 알고리즘 | 목적 | 음수 간선 | 음수 사이클 탐지 | 대표 복잡도 |
|---|---|---:|---:|---|
| 다익스트라 | 단일 시작점 최단 경로 | 불가 | 불가 | 우선순위 큐 사용 시 보통 `O((V + E) log V)` |
| 벨만-포드 | 단일 시작점 최단 경로 | 가능 | 가능 | `O(VE)` |
| 플로이드-워셜 | 모든 쌍 최단 경로 | 가능 | 일부 방식으로 확인 가능 | `O(V^3)` |

단, 플로이드-워셜도 음수 간선은 처리할 수 있지만, **음수 사이클이 존재하면 최단 경로 값이 정의되지 않을 수 있다.** 음수 사이클을 계속 돌면 비용을 무한히 낮출 수 있기 때문이다.

## 내부 동작 원리

## 1. 다익스트라 알고리즘

다익스트라는 “현재까지 알려진 가장 짧은 거리의 정점부터 확정한다”는 탐욕적 전략을 사용한다. 핵심 전제는 **간선 가중치가 음수가 아니어야 한다**는 점이다. 음수 간선이 존재하면 나중에 더 짧은 경로가 발견될 수 있어 이미 확정한 거리가 깨질 수 있다.

### 동작 과정

1. 시작 정점의 거리를 `0`으로 설정한다.
2. 나머지 정점의 거리는 무한대 `INF`로 초기화한다.
3. 아직 처리하지 않은 정점 중 현재 거리가 가장 작은 정점을 선택한다.
4. 해당 정점에서 나가는 모든 간선을 확인하며 거리 값을 완화(relaxation)한다.
5. 더 짧은 경로가 발견되면 거리 배열을 갱신한다.
6. 모든 정점을 처리하거나 우선순위 큐가 빌 때까지 반복한다.

### 완화 연산

간선 `u -> v`의 가중치가 `w`일 때:

```text
if dist[v] > dist[u] + w:
    dist[v] = dist[u] + w
```

이는 “기존에 알고 있던 v까지의 거리보다 u를 거쳐 가는 거리가 더 짧으면 갱신한다”는 의미다.

### 다이어그램 설명

예를 들어 다음 그래프가 있다고 하자.

```text
A --2--> B --3--> D
|        |
5        1
v        v
C --2--> D
```

시작점이 `A`라면 초기 상태는 다음과 같다.

```text
dist[A] = 0
dist[B] = INF
dist[C] = INF
dist[D] = INF
```

`A`에서 출발해 인접 정점을 확인한다.

```text
A -> B 비용 2  => dist[B] = 2
A -> C 비용 5  => dist[C] = 5
```

현재 가장 짧은 미확정 정점은 `B`이다. `B`를 처리한다.

```text
B -> D 비용 3  => dist[D] = dist[B] + 3 = 5
B -> C 비용 1  => dist[C] = min(5, 2 + 1) = 3
```

이후 `C`를 처리하면:

```text
C -> D 비용 2  => dist[D] = min(5, 3 + 2) = 5
```

최종 결과:

```text
A까지 0
B까지 2
C까지 3
D까지 5
```

다익스트라는 보통 인접 리스트와 우선순위 큐를 함께 사용한다. 이 경우 모든 간선을 확인하면서도 가장 가까운 정점을 빠르게 선택할 수 있다.

## 2. 벨만-포드 알고리즘

벨만-포드는 모든 간선을 반복적으로 완화하는 방식이다. 다익스트라와 달리 음수 간선이 있어도 사용할 수 있다. 핵심 아이디어는 “최단 경로는 음수 사이클이 없다면 최대 `V - 1`개의 간선만 사용한다”는 점이다. 정점이 `V`개인 그래프에서 단순 경로는 최대 `V - 1`개의 간선을 가지기 때문이다.

### 동작 과정

1. 시작 정점의 거리를 `0`, 나머지는 `INF`로 초기화한다.
2. 전체 간선 목록을 `V - 1`번 반복하며 완화한다.
3. 한 번 더 전체 간선을 완화해본다.
4. 이때도 거리 갱신이 발생하면 음수 사이클이 존재한다고 판단한다.

### 다이어그램 설명

```text
A --4--> B
A --5--> C
C ---3--> B
B --2--> D
```

여기서 `C -> B`의 가중치가 `-3`이라고 하자.

초기 상태:

```text
dist[A] = 0
dist[B] = INF
dist[C] = INF
dist[D] = INF
```

1회차 완화:

```text
A -> B: dist[B] = 4
A -> C: dist[C] = 5
C -> B: dist[B] = min(4, 5 + (-3)) = 2
B -> D: dist[D] = 4
```

음수 간선 `C -> B` 때문에 `B`까지의 최단 거리가 기존 `4`에서 `2`로 줄어들었다. 다익스트라에서는 이런 상황이 문제가 될 수 있지만, 벨만-포드는 모든 간선을 반복해서 확인하므로 올바르게 처리할 수 있다.

### 음수 사이클 탐지

다음과 같은 사이클이 있다고 하자.

```text
B --1--> C
C ---3--> B
```

사이클 비용은:

```text
1 + (-3) = -2
```

이 사이클을 반복해서 돌면 경로 비용이 계속 감소한다. 따라서 특정 정점까지의 “최단” 거리는 정의되지 않는다. 벨만-포드는 `V - 1`번 완화 후에도 추가 갱신이 발생하는지 확인하여 이런 음수 사이클을 탐지한다.

## 3. 플로이드-워셜 알고리즘

플로이드-워셜은 모든 정점 쌍 `(i, j)`에 대해 최단 거리를 계산하는 알고리즘이다. 핵심 아이디어는 동적 계획법이다. “정점 `k`를 중간 경유지로 사용할 수 있을 때, `i`에서 `j`로 가는 최단 거리가 더 짧아지는가?”를 반복적으로 검사한다.

### 점화식

```text
dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
```

여기서 `k`는 중간 경유지로 허용되는 정점이다.

### 동작 과정

1. `V x V` 거리 행렬을 만든다.
2. 자기 자신으로 가는 거리는 `0`으로 설정한다.
3. 직접 연결된 간선의 가중치를 행렬에 넣는다.
4. 직접 연결되지 않은 경우는 `INF`로 둔다.
5. 모든 정점 `k`에 대해, 모든 `(i, j)` 쌍을 검사하며 거리 값을 갱신한다.

### 다이어그램 설명

초기 거리 행렬이 다음과 같다고 하자.

```text
      A    B    C
A     0    4    INF
B   INF    0    2
C     1   INF   0
```

`B`를 경유지로 사용할 수 있다면 `A -> C`는 다음과 같이 갱신된다.

```text
A -> C 기존 거리: INF
A -> B -> C 거리: 4 + 2 = 6
따라서 dist[A][C] = 6
```

이후 `C`를 경유지로 사용할 수 있다면 `B -> A`도 갱신된다.

```text
B -> A 기존 거리: INF
B -> C -> A 거리: 2 + 1 = 3
따라서 dist[B][A] = 3
```

플로이드-워셜은 구현이 단순하지만 `O(V^3)`의 시간 복잡도와 `O(V^2)`의 공간 복잡도를 사용한다. 따라서 정점 수가 큰 그래프에는 부적합할 수 있다.

## 비교 정리

| 항목 | 다익스트라 | 벨만-포드 | 플로이드-워셜 |
|---|---|---|---|
| 문제 유형 | 단일 시작점 | 단일 시작점 | 모든 쌍 |
| 음수 간선 | 불가 | 가능 | 가능 |
| 음수 사이클 | 탐지 불가 | 탐지 가능 | `dist[i][i] < 0` 등으로 확인 가능 |
| 시간 복잡도 | 보통 `O((V+E) log V)` | `O(VE)` | `O(V^3)` |
| 공간 복잡도 | 보통 `O(V+E)` | 보통 `O(V+E)` | `O(V^2)` |
| 적합한 상황 | 음수 없는 큰 그래프 | 음수 간선 또는 음수 사이클 검사 | 모든 정점 쌍 거리 필요 |

## 실제 시스템 연결

## 1. 네트워크 라우팅

최단 경로 알고리즘은 실제 네트워크 라우팅의 핵심 개념과 밀접하다.

### OSPF와 다익스트라

OSPF(Open Shortest Path First)는 링크 상태 라우팅 프로토콜이며, 네트워크 토폴로지 정보를 기반으로 최단 경로 트리를 계산한다. OSPF는 SPF(Shortest Path First) 계산에 다익스트라 알고리즘을 사용한다고 알려져 있다. 각 링크에는 cost가 부여되고, 라우터는 목적지까지 cost 합이 가장 낮은 경로를 선택한다.

```text
Router A
 ├─ cost 10 ─ Router B ─ cost 10 ─ Network X
 └─ cost 30 ─ Router C ─ cost 5  ─ Network X
```

위 예시에서 A에서 Network X로 가는 경로는 다음과 같이 비교된다.

```text
A -> B -> X = 20
A -> C -> X = 35
```

따라서 더 낮은 cost의 경로가 선택된다.

### RIP와 벨만-포드 계열

RIP(Routing Information Protocol)는 거리 벡터 라우팅 프로토콜이다. 거리 벡터 방식은 벨만-포드 알고리즘의 아이디어와 관련이 있다. 각 라우터는 인접 라우터로부터 목적지까지의 거리 정보를 받아 자신의 라우팅 테이블을 갱신한다.

다만 실제 프로토콜은 단순한 벨만-포드 구현만으로 동작하지 않고, 라우팅 루프 완화를 위해 split horizon, route poisoning 같은 기법을 사용한다.

## 2. Linux 네트워크

Linux 커널 자체가 일반 애플리케이션 레벨에서 다익스트라를 직접 호출해 라우팅 테이블을 만드는 구조라고 단정하기는 어렵다. 일반적인 Linux 라우팅은 커널의 라우팅 테이블, 정책 기반 라우팅, netlink 인터페이스, iproute2 도구 등을 통해 관리된다.

예를 들어:

```bash
ip route
ip rule
ip addr
```

명령어로 라우팅 상태를 확인할 수 있다. 실제 최단 경로 계산은 Linux 호스트 내부보다는 라우팅 데몬에서 수행되는 경우가 많다. 예를 들어 FRRouting(FRR), BIRD 같은 라우팅 소프트웨어가 OSPF, BGP 등 프로토콜을 구현하고, 계산된 경로를 커널 라우팅 테이블에 반영할 수 있다.

## 3. Nginx와 경로 선택

Nginx는 최단 경로 알고리즘을 직접 사용하는 대표 사례라기보다는, 요청을 업스트림 서버로 분산하는 로드 밸런서 역할을 수행한다. Nginx의 기본 로드 밸런싱 방식에는 round-robin, least connections, IP hash 등이 있다. 이는 그래프 최단 경로라기보다는 트래픽 분산 전략에 가깝다.

하지만 대규모 시스템 설계 관점에서는 다음과 같은 문제를 최단 경로 문제로 모델링할 수 있다.

```text
Client -> Edge Proxy -> Regional Gateway -> Service Cluster -> Database
```

각 구간의 지연 시간, 비용, 장애율을 가중치로 두면 “가장 낮은 비용의 서비스 호출 경로”를 계산하는 문제로 해석할 수 있다.

## 4. 지도 및 물류 시스템

지도 서비스나 물류 시스템은 도로, 교차로, 배송 거점 등을 그래프로 표현한다. 간선 가중치는 거리, 예상 시간, 통행료, 교통량 등을 반영할 수 있다. 음수 가중치가 없는 도로 네트워크에서는 다익스트라 또는 A* 같은 알고리즘이 자주 사용된다. 다만 실제 상용 지도 서비스는 단순 다익스트라만 사용하는 것이 아니라, 계층적 라우팅, 휴리스틱, 실시간 교통 정보, 사전 계산 기법 등을 함께 사용할 수 있다.

⚠️ 확인 필요: 특정 상용 지도 서비스가 내부적으로 어떤 알고리즘 조합을 사용하는지는 공개되지 않은 경우가 많으므로, 서비스별 구현을 단정해서는 안 된다.

## 클라우드 연결

## 1. AWS 네트워크와 최단 경로 개념

AWS VPC에서는 라우팅 테이블, 서브넷, 인터넷 게이트웨이, NAT 게이트웨이, Transit Gateway 등을 통해 패킷 전달 경로가 결정된다. AWS 사용자가 직접 다익스트라나 벨만-포드를 실행해 VPC 라우팅을 구성하는 것은 아니지만, 네트워크 설계자는 경로 비용, 지연 시간, 가용성, 장애 도메인을 고려해야 한다.

예를 들어 멀티 리전 아키텍처에서는 다음과 같은 경로 선택 문제가 발생할 수 있다.

```text
User
 ├─ Region A ALB -> Service A -> DB Replica A
 └─ Region B ALB -> Service B -> DB Replica B
```

사용자와 리전 간 지연 시간, 서비스 상태, 데이터 일관성 요구사항을 가중치로 보면 경로 최적화 문제로 볼 수 있다.

## 2. AWS Transit Gateway

AWS Transit Gateway는 여러 VPC와 온프레미스 네트워크를 중앙에서 연결하는 허브 역할을 한다. Transit Gateway 라우팅 테이블을 통해 어떤 네트워크로 트래픽을 보낼지 결정한다. 이는 그래프 관점에서 여러 네트워크 노드와 연결 간선의 경로 선택 문제로 해석할 수 있다.

다만 AWS Transit Gateway가 내부적으로 특정 최단 경로 알고리즘을 사용한다고 일반화해서 말하기는 어렵다.

⚠️ 확인 필요: AWS Transit Gateway 내부 라우팅 구현이 다익스트라, 벨만-포드, 플로이드-워셜 중 하나를 직접 사용한다고 공개적으로 보장된 것은 아니다.

## 3. Kubernetes 네트워크

Kubernetes에서는 Pod, Service, Node, Ingress, NetworkPolicy 등이 네트워크 경로에 관여한다. 일반적으로 Kubernetes 사용자가 최단 경로 알고리즘을 직접 다루지는 않는다. 하지만 서비스 메시나 CNI(Container Network Interface) 플러그인, 멀티 클러스터 라우팅에서는 경로 최적화 문제가 나타날 수 있다.

예시:

```text
Client
  -> Ingress Controller
  -> Service
  -> Pod A / Pod B / Pod C
```

여기서 각 Pod까지의 지연 시간, 부하, 장애 상태를 가중치로 보면 요청을 어느 Pod로 보낼지 결정하는 문제가 된다. 다만 Kubernetes 기본 Service 로드밸런싱은 전통적인 그래프 최단 경로 알고리즘이라기보다는 kube-proxy, iptables, IPVS 또는 CNI 구현에 따라 트래픽을 분산하는 구조에 가깝다.

## 4. Service Mesh와 경로 비용

Istio, Linkerd 같은 서비스 메시에서는 서비스 간 트래픽 제어, 재시도, 타임아웃, 서킷 브레이커, 트래픽 분할을 관리한다. 서비스 호출 관계는 다음처럼 그래프로 표현할 수 있다.

```text
frontend
 ├─> user-service
 │     └─> user-db
 └─> order-service
       ├─> payment-service
       └─> inventory-service
```

이때 각 간선의 지연 시간, 실패율, 비용을 수집하면 “어떤 호출 경로가 가장 안정적인가”, “장애가 발생했을 때 우회 경로는 무엇인가”를 분석할 수 있다. 실제 서비스 메시가 내부적으로 다익스트라를 항상 사용한다고 볼 수는 없지만, 관측 데이터 기반 경로 분석에는 최단 경로 모델이 유용하다.

## 5. Docker와 컨테이너 네트워크

Docker 네트워크는 bridge, host, overlay 등의 네트워크 모드를 제공한다. 단일 호스트 Docker bridge 네트워크에서는 일반적으로 최단 경로 알고리즘이 직접적으로 드러나지 않는다. 그러나 여러 호스트에 걸친 overlay 네트워크나 마이크로서비스 호출 그래프에서는 컨테이너 간 통신 비용을 그래프로 모델링할 수 있다.

```text
container-a -> container-b -> container-c
```

각 호출의 latency를 가중치로 기록하면 병목 경로 분석, 장애 전파 분석, 최적 배치 문제에 활용할 수 있다.

## 보안 연결

## 1. 라우팅 공격과 최단 경로

최단 경로 알고리즘이 적용되는 네트워크에서는 경로 비용이나 라우팅 정보를 조작하는 공격이 문제가 될 수 있다. 공격자가 낮은 비용의 경로를 허위로 광고하면 트래픽이 공격자-controlled 경로로 우회될 수 있다.

예를 들어 거리 벡터 라우팅에서는 잘못된 거리 정보가 전파되면 라우팅 루프나 비효율적인 경로 선택이 발생할 수 있다. 링크 상태 라우팅에서도 잘못된 링크 상태 정보가 유입되면 전체 토폴로지 계산 결과가 왜곡될 수 있다.

## 2. BGP 하이재킹

BGP(Border Gateway Protocol)는 인터넷의 자율 시스템 간 라우팅에 사용된다. BGP는 일반적인 의미의 최단 경로 알고리즘이라기보다 정책 기반 path vector 프로토콜이다. 하지만 경로 선택 정보를 조작하거나 잘못 광고하면 트래픽이 의도치 않은 AS로 이동할 수 있다. 이를 BGP 하이재킹이라고 한다.

보안 모범 사례:

- RPKI(Route Origin Authorization)를 통한 경로 출처 검증
- Prefix filtering
- IRR 기반 필터링
- 라우팅 모니터링
- 비정상 경로 변경 알림 설정

## 3. 음수 사이클과 비정상 비용 모델

보안 분석이나 리스크 모델링에서 간선 가중치를 “위험도” 또는 “비용”으로 둘 때, 음수 가중치를 도입할 수 있다. 예를 들어 보상, 캐시 히트, 정책 우대 등을 음수 비용으로 표현하는 경우가 있다. 이때 음수 사이클이 존재하면 비용이 무한히 낮아지는 비현실적인 모델이 된다.

벨만-포드는 이런 음수 사이클을 탐지할 수 있으므로, 비용 모델 검증에 유용하다.

```text
A -> B 비용 -2
B -> C 비용 -2
C -> A 비용 1
총합 = -3
```

이 사이클을 반복하면 비용이 계속 낮아지므로 정상적인 최단 경로가 존재하지 않는다.

## 4. 클라우드 네트워크 보안

클라우드 환경에서는 보안 그룹, NACL, 라우팅 테이블, 방화벽 정책, 서비스 메시 정책이 복합적으로 적용된다. 네트워크 접근 가능성을 그래프로 모델링하면 공격 경로 분석에 활용할 수 있다.

예시:

```text
Internet
  -> Public ALB
  -> Web Service
  -> Internal API
  -> Database
```

각 간선은 접근 가능 여부, 인증 필요 여부, 권한 수준, 취약점 존재 여부를 나타낼 수 있다. 공격자가 어느 경로를 통해 민감 자원에 도달할 수 있는지 분석하는 문제는 그래프 탐색 및 최단 경로 문제로 해석할 수 있다. 여기서 “최단”은 거리보다 “가장 적은 권한 상승 단계”, “가장 낮은 탐지 가능성”, “가장 적은 취약점 체인 길이”를 의미할 수 있다.

## 5. 알고리즘 구현 보안

최단 경로 알고리즘 구현에서도 다음과 같은 문제가 발생할 수 있다.

- `INF` 값 설정 오류로 인한 정수 오버플로우
- 매우 큰 그래프 입력으로 인한 메모리 고갈
- 음수 간선이 있는데 다익스트라를 사용하는 논리 취약점
- 음수 사이클을 확인하지 않아 잘못된 결과 사용
- 외부 입력 그래프에 대한 검증 부족
- 우선순위 큐에 오래된 거리 정보가 남는 경우 처리 누락

예를 들어 다익스트라 구현에서는 다음 조건을 자주 사용한다.

```python
if current_distance > dist[node]:
    continue
```

이는 우선순위 큐에 들어 있는 오래된 경로 정보를 무시하기 위한 처리다. 이 처리가 없어도 정답이 나오는 경우가 많지만, 불필요한 연산이 크게 증가할 수 있다.

## 6. 보안 모범 사례

- 입력 그래프의 정점 수, 간선 수 제한
- 가중치 범위 검증
- 음수 간선 존재 여부 확인
- 다익스트라 사용 전 음수 가중치가 없는지 검증
- 벨만-포드 사용 시 음수 사이클 탐지 결과 처리
- `INF + weight` 연산 전 `dist[u] != INF` 확인
- 정수 범위가 충분한 자료형 사용
- 클라우드 네트워크 경로 변경에 대한 감사 로그 활성화
- 라우팅 테이블, 보안 그룹, 방화벽 정책 변경 감시

## 면접 질문

**Q1. 다익스트라 알고리즘은 왜 음수 간선이 있으면 안 되나요?**  
> 핵심 답변: 다익스트라는 현재 가장 짧은 거리의 정점을 선택해 그 거리를 확정하는 탐욕적 알고리즘이다. 음수 간선이 있으면 나중에 더 짧은 경로가 발견될 수 있어 이미 확정한 값이 깨질 수 있다. 따라서 음수 가중치가 없는 그래프에서 사용해야 한다.

**Q2. 벨만-포드 알고리즘이 음수 사이클을 탐지하는 원리는 무엇인가요?**  
> 핵심 답변: 정점이 `V`개인 그래프에서 음수 사이클이 없다면 최단 경로는 최대 `V - 1`개의 간선만 사용한다. 따라서 모든 간선을 `V - 1`번 완화한 뒤에도 추가 갱신이 발생하면, 비용을 계속 줄일 수 있는 음수 사이클이 존재한다고 판단한다.

**Q3. 플로이드-워셜 알고리즘의 핵심 점화식은 무엇인가요?**  
> 핵심 답변: `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`이다. 이는 정점 `k`를 중간 경유지로 사용할 때, `i`에서 `j`로 직접 가는 기존 경로보다 `i -> k -> j` 경로가 더 짧으면 갱신한다는 의미다.

**Q4. 세 알고리즘의 사용 상황을 어떻게 구분하나요?**  
> 핵심 답변: 음수 간선이 없고 한 시작점에서의 최단 거리가 필요하면 다익스트라가 적합하다. 음수 간선이 있거나 음수 사이클 탐지가 필요하면 벨만-포드를 사용한다. 모든 정점 쌍 사이의 최단 거리가 필요하고 정점 수가 크지 않다면 플로이드-워셜을 사용한다.

**Q5. 플로이드-워셜로 음수 사이클을 어떻게 확인할 수 있나요?**  
> 핵심 답변: 알고리즘 수행 후 거리 행렬의 대각 원소 `dist[i][i]`를 확인한다. 어떤 정점 `i`에 대해 `dist[i][i] < 0`이면, 해당 정점에서 출발해 다시 자기 자신으로 돌아오는 음수 비용 사이클이 존재한다고 볼 수 있다.
