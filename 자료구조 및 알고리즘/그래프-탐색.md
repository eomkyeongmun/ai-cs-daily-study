# 그래프 탐색 - BFS(너비 우선 탐색), DFS(깊이 우선 탐색)

## 핵심 개념

그래프 탐색(Graph Traversal)은 정점(Vertex, Node)과 간선(Edge)으로 구성된 그래프 자료구조에서 특정 시작점으로부터 연결된 정점들을 체계적으로 방문하는 알고리즘이다. 대표적인 방식이 BFS(Breadth-First Search, 너비 우선 탐색)와 DFS(Depth-First Search, 깊이 우선 탐색)이다.

BFS는 시작 정점에서 가까운 정점부터 차례대로 탐색한다. 즉, 시작점으로부터 거리 1인 정점들을 모두 방문한 뒤, 거리 2인 정점들을 방문하는 방식이다. 이 특성 때문에 **간선 가중치가 없는 그래프에서 최단 경로를 찾는 데 적합**하다. BFS는 보통 큐(Queue)를 사용하여 구현한다.

DFS는 한 방향으로 갈 수 있는 만큼 깊게 들어간 뒤, 더 이상 갈 곳이 없으면 이전 정점으로 되돌아와 다른 경로를 탐색한다. 보통 재귀 호출 또는 스택(Stack)을 사용한다. DFS는 그래프의 연결 요소 탐색, 사이클 탐지, 위상 정렬, 백트래킹 문제에서 자주 사용된다.

그래프 탐색이 중요한 이유는 현실 세계의 많은 문제가 그래프로 모델링되기 때문이다. 예를 들어 소셜 네트워크의 친구 관계, 웹 페이지 링크 구조, 네트워크 라우팅, 파일 시스템 디렉터리 구조, 서비스 의존성 그래프, 클라우드 리소스 관계 등이 모두 그래프 형태로 표현될 수 있다. BFS와 DFS는 이러한 구조에서 경로를 찾고, 연결성을 확인하며, 의존 관계를 분석하고, 문제 공간을 탐색하는 기본 도구로 활용된다.

시간 복잡도는 인접 리스트 기준으로 BFS와 DFS 모두 일반적으로 `O(V + E)`이다. 여기서 `V`는 정점 수, `E`는 간선 수이다. 인접 행렬을 사용할 경우 모든 정점 간 연결 여부를 확인해야 하므로 탐색 과정에서 `O(V^2)`가 될 수 있다.

## 내부 동작 원리

## 1. 그래프 표현 방식

그래프 탐색을 구현하기 전에 그래프를 메모리에 표현해야 한다. 대표적인 방식은 다음과 같다.

### 인접 리스트

각 정점마다 연결된 정점 목록을 저장한다.

```text
A: B, C
B: A, D, E
C: A, F
D: B
E: B, F
F: C, E
```

- 공간 복잡도: `O(V + E)`
- 희소 그래프에 적합
- BFS/DFS에서 자주 사용

### 인접 행렬

정점 간 연결 여부를 2차원 배열로 저장한다.

```text
    A B C D E F
A [ 0 1 1 0 0 0 ]
B [ 1 0 0 1 1 0 ]
C [ 1 0 0 0 0 1 ]
D [ 0 1 0 0 0 0 ]
E [ 0 1 0 0 0 1 ]
F [ 0 0 1 0 1 0 ]
```

- 공간 복잡도: `O(V^2)`
- 밀집 그래프에 적합
- 특정 두 정점의 연결 여부 확인은 빠름

## 2. BFS 내부 동작 원리

BFS는 큐를 사용한다. 큐는 FIFO(First-In, First-Out) 구조이므로 먼저 발견된 정점이 먼저 처리된다.

예제 그래프:

```text
        A
      /   \
     B     C
    / \     \
   D   E --- F
```

인접 리스트:

```text
A: B, C
B: A, D, E
C: A, F
D: B
E: B, F
F: C, E
```

A에서 BFS를 시작한다고 가정한다.

### BFS 진행 과정

```text
초기 상태:
Queue: [A]
Visited: {A}

1단계:
A를 큐에서 꺼냄
A의 이웃 B, C 방문
Queue: [B, C]
Visited: {A, B, C}

2단계:
B를 큐에서 꺼냄
B의 이웃 D, E 방문
Queue: [C, D, E]
Visited: {A, B, C, D, E}

3단계:
C를 큐에서 꺼냄
C의 이웃 F 방문
Queue: [D, E, F]
Visited: {A, B, C, D, E, F}

4단계 이후:
D, E, F를 차례대로 꺼냄
이미 방문한 정점만 있으므로 추가 없음
```

방문 순서는 인접 리스트의 순서에 따라 달라질 수 있다. 위 예에서는 다음과 같다.

```text
A → B → C → D → E → F
```

### BFS 의사코드

```text
BFS(graph, start):
    create empty queue
    visited = empty set

    enqueue start
    mark start as visited

    while queue is not empty:
        current = dequeue

        for each neighbor of current:
            if neighbor is not visited:
                mark neighbor as visited
                enqueue neighbor
```

### BFS 특징

- 큐를 사용한다.
- 가까운 정점부터 탐색한다.
- 무가중치 그래프에서 최단 거리 계산에 적합하다.
- 레벨 단위 탐색이 가능하다.
- 최단 경로 복원을 위해 부모 배열 또는 predecessor map을 함께 사용할 수 있다.

예를 들어 최단 경로 복원을 위해 다음과 같은 정보를 저장할 수 있다.

```text
parent[B] = A
parent[C] = A
parent[D] = B
parent[E] = B
parent[F] = C
```

A에서 F까지의 경로를 복원하면 다음과 같다.

```text
F ← C ← A
즉, A → C → F
```

## 3. DFS 내부 동작 원리

DFS는 한 경로를 끝까지 탐색한 뒤 되돌아오는 방식이다. 재귀 호출 또는 스택을 사용한다.

같은 그래프에서 A부터 DFS를 수행한다.

```text
        A
      /   \
     B     C
    / \     \
   D   E --- F
```

인접 리스트 순서를 다음과 같이 둔다.

```text
A: B, C
B: A, D, E
C: A, F
D: B
E: B, F
F: C, E
```

### 재귀 DFS 진행 과정

```text
DFS(A)
  방문 A
  DFS(B)
    방문 B
    DFS(D)
      방문 D
      B는 이미 방문됨
    DFS(E)
      방문 E
      DFS(F)
        방문 F
        DFS(C)
          방문 C
          A는 이미 방문됨
```

방문 순서는 인접 리스트 순서에 따라 다음과 같을 수 있다.

```text
A → B → D → E → F → C
```

### DFS 의사코드: 재귀 방식

```text
DFS(graph, current, visited):
    mark current as visited

    for each neighbor of current:
        if neighbor is not visited:
            DFS(graph, neighbor, visited)
```

### DFS 의사코드: 명시적 스택 방식

```text
DFS_iterative(graph, start):
    create empty stack
    visited = empty set

    push start

    while stack is not empty:
        current = pop

        if current is not visited:
            mark current as visited

            for each neighbor of current:
                if neighbor is not visited:
                    push neighbor
```

명시적 스택 방식에서는 이웃을 스택에 넣는 순서에 따라 방문 순서가 재귀 방식과 달라질 수 있다. 재귀 DFS와 동일한 순서를 원하면 이웃을 역순으로 스택에 넣는 방식이 자주 사용된다.

### DFS 특징

- 재귀 호출 또는 스택을 사용한다.
- 한 경로를 깊게 탐색한다.
- 그래프의 연결 요소 찾기, 사이클 탐지, 위상 정렬, 백트래킹에 적합하다.
- 재귀 방식은 그래프가 매우 깊을 경우 호출 스택 초과가 발생할 수 있다.
- 방문 여부를 관리하지 않으면 사이클이 있는 그래프에서 무한 루프가 발생할 수 있다.

## 4. BFS와 DFS 비교

| 항목 | BFS | DFS |
|---|---|---|
| 탐색 방식 | 가까운 정점부터 레벨 단위 탐색 | 한 경로를 깊게 탐색 |
| 주요 자료구조 | 큐 | 스택 또는 재귀 |
| 최단 경로 | 무가중치 그래프에서 적합 | 일반적으로 최단 경로 보장 안 함 |
| 메모리 사용 | 같은 레벨의 정점을 많이 저장할 수 있음 | 깊이에 비례하지만 재귀 스택 위험 있음 |
| 대표 활용 | 최단 거리, 레벨 탐색, 네트워크 전파 | 사이클 탐지, 위상 정렬, 백트래킹 |
| 시간 복잡도 | `O(V + E)` | `O(V + E)` |
| 방문 순서 | 인접 리스트 순서에 영향 | 인접 리스트 순서에 영향 |

## 실제 시스템 연결

## 1. Linux 파일 시스템 탐색

파일 시스템은 디렉터리와 파일을 노드로, 포함 관계를 간선으로 볼 수 있다. 디렉터리 트리 탐색은 DFS와 BFS 모두로 모델링할 수 있다.

예를 들어 재귀적으로 하위 디렉터리를 탐색하는 작업은 DFS와 유사하다.

```text
/home
 ├── user
 │   ├── docs
 │   └── images
 └── logs
```

DFS 방식은 `/home/user/docs`처럼 한 경로를 끝까지 내려간 뒤 다른 디렉터리로 이동한다. 반면 BFS 방식은 `/home`의 바로 아래 항목들을 먼저 본 뒤, 그 다음 깊이의 항목들을 탐색한다.

실제 명령어 `find`는 파일 시스템 계층을 순회하는 데 사용된다. 내부 구현 세부는 운영체제와 구현체에 따라 다를 수 있으므로 특정 탐색 방식으로 단정하기는 어렵다.  
⚠️ 확인 필요: 사용 중인 `find` 구현체가 내부적으로 어떤 순회 전략을 사용하는지는 GNU findutils, BSD find 등 구현별 문서를 확인해야 한다.

## 2. 네트워크 연결성 분석

서버, 라우터, 스위치, 서비스 엔드포인트를 정점으로 보고, 연결 관계를 간선으로 보면 네트워크는 그래프로 표현된다. BFS는 특정 노드에서 몇 홉(hop) 이내에 도달 가능한 노드를 찾는 데 적합하다.

예를 들어 장애 분석 시 다음과 같은 질문을 할 수 있다.

```text
- 서버 A에서 서버 F까지 도달 가능한가?
- 최소 몇 개의 네트워크 장비를 거쳐야 하는가?
- 특정 라우터 장애 시 어떤 영역이 고립되는가?
```

무가중치 홉 수 기준이라면 BFS를 사용해 최소 홉 경로를 찾을 수 있다. 다만 실제 네트워크 라우팅은 링크 비용, 정책, 프로토콜, ACL, 방화벽 규칙 등을 고려하므로 단순 BFS만으로는 충분하지 않다.

## 3. 웹 크롤러

웹 페이지를 정점, 하이퍼링크를 간선으로 보면 웹은 거대한 방향 그래프이다. 웹 크롤러는 특정 URL에서 시작해 링크를 따라가며 페이지를 수집한다.

BFS 방식 크롤링은 시작 URL에서 가까운 링크부터 넓게 수집한다.

```text
Depth 0: example.com
Depth 1: example.com/about, example.com/products
Depth 2: example.com/products/item1, ...
```

DFS 방식 크롤링은 특정 링크를 따라 깊게 들어간 뒤 돌아온다. BFS는 크롤링 깊이를 제한하거나 사이트 구조를 레벨 단위로 파악하는 데 유리하다. DFS는 특정 경로를 깊게 조사하는 데 사용할 수 있지만, 깊이 제한이 없으면 매우 긴 링크 체인을 따라가며 자원이 낭비될 수 있다.

웹 크롤러에서는 반드시 방문 URL 집합을 관리해야 한다. 그렇지 않으면 순환 링크 구조 때문에 같은 페이지를 반복 수집할 수 있다.

## 4. 의존성 그래프 분석

소프트웨어 패키지, 빌드 시스템, 마이크로서비스 간 의존성은 그래프로 표현된다.

예를 들어 다음과 같은 서비스 의존성이 있다고 하자.

```text
Frontend → API Gateway → Auth Service
Frontend → API Gateway → Order Service → Payment Service
```

DFS는 의존성 체인을 깊게 따라가며 순환 의존성을 탐지하는 데 유용하다. 방향 그래프에서 DFS를 사용할 때 방문 상태를 `미방문`, `방문 중`, `방문 완료`로 나누면 사이클 탐지가 가능하다.

```text
방문 중인 노드를 다시 만남 → 사이클 존재
```

이 방식은 빌드 순서 계산, 패키지 의존성 검증, 서비스 영향도 분석에 응용된다.

## 5. Nginx와 요청 라우팅 구조

Nginx 자체가 BFS나 DFS를 직접 핵심 알고리즘으로 사용한다고 일반화하기는 어렵다. 그러나 Nginx 설정의 `location` 매칭, upstream 선택, 리버스 프록시 경로 분석 등은 트리 또는 그래프 구조로 모델링해 이해할 수 있다.

예를 들어 여러 서비스로 요청이 전달되는 구조는 다음과 같이 그래프로 표현할 수 있다.

```text
Client
  ↓
Nginx
  ↓
API Gateway
  ↓
Service A / Service B / Service C
```

장애 분석에서는 이 그래프를 탐색하여 특정 클라이언트 요청이 어떤 백엔드 서비스까지 도달하는지 확인할 수 있다. BFS는 특정 지점에서 가까운 의존 서비스를 우선 확인하는 데 적합하고, DFS는 하나의 요청 경로를 끝까지 추적하는 데 적합하다.

## 클라우드 연결

## 1. Kubernetes 리소스 관계 탐색

Kubernetes 환경에서는 Pod, Service, Deployment, ReplicaSet, ConfigMap, Secret, Ingress 등이 서로 관계를 가진다. 이를 그래프로 모델링하면 리소스 영향도 분석에 BFS/DFS를 사용할 수 있다.

예:

```text
Ingress
  ↓
Service
  ↓
Pod
  ↓
ConfigMap / Secret
```

BFS는 특정 리소스에서 가까운 의존 리소스를 단계별로 확인하는 데 적합하다. 예를 들어 `Ingress → Service → Pod` 순서로 접근 경로를 확인할 수 있다.

DFS는 특정 워크로드가 참조하는 리소스를 깊게 따라가며 문제 원인을 추적하는 데 유용하다.

```text
Deployment
  ↓
ReplicaSet
  ↓
Pod
  ↓
Volume
  ↓
PersistentVolumeClaim
  ↓
PersistentVolume
```

이런 관계 탐색은 장애 분석, 리소스 정리, 보안 감사, 권한 영향도 분석에 활용될 수 있다.

## 2. Docker 이미지 레이어와 의존 관계

Docker 이미지는 여러 레이어(layer)로 구성된다. 이미지의 기반 이미지와 파생 이미지를 그래프로 표현하면 의존 관계를 추적할 수 있다.

```text
ubuntu base image
  ↓
python runtime image
  ↓
application image
```

DFS는 특정 애플리케이션 이미지가 어떤 기반 이미지에서 파생되었는지 깊게 추적하는 데 적합하다. BFS는 여러 이미지가 공유하는 공통 기반 레이어나 가까운 의존 이미지를 분석하는 데 사용할 수 있다.

다만 Docker 이미지 내부 구현 자체가 BFS/DFS로 동작한다고 단정해서는 안 된다. 여기서는 이미지 및 레이어 관계를 그래프로 모델링했을 때 탐색 알고리즘을 적용할 수 있다는 의미이다.

---

## 3. AWS 리소스 관계 분석

AWS 환경에서는 VPC, Subnet, Route Table, Security Group, EC2 Instance, Load Balancer, Target Group, IAM Role 등 많은 리소스가 서로 연결된다. 이 관계를 그래프로 구성하면 접근 가능성 분석이나 영향도 분석에 BFS/DFS를 적용할 수 있다.

예:

```text
Internet
  ↓
Internet Gateway
  ↓
Route Table
  ↓
Public Subnet
  ↓
Load Balancer
  ↓
Target Group
  ↓
EC2 Instance
```

BFS는 인터넷에서 특정 EC2까지 몇 단계의 리소스를 거쳐 접근 가능한지 분석하는 데 적합하다. DFS는 하나의 접근 경로를 끝까지 추적하여 보안 그룹, 네트워크 ACL, 라우팅 조건을 확인하는 데 활용할 수 있다.

AWS IAM에서도 사용자, 그룹, 역할, 정책의 관계를 그래프로 볼 수 있다.

```text
User → Group → Policy → Permission
Role → Policy → Permission
```

권한 상승 가능성 분석에서는 이러한 관계 그래프를 탐색해 특정 주체가 어떤 권한에 도달할 수 있는지 확인한다.

---

## 4. AWS Neptune과 그래프 데이터베이스

AWS Neptune은 관리형 그래프 데이터베이스 서비스이다. 그래프 데이터베이스는 정점과 간선을 저장하고 질의하는 데 특화되어 있다. BFS, DFS 같은 그래프 탐색 개념은 그래프 데이터베이스 질의의 기초가 된다.

예를 들어 다음과 같은 질의를 생각할 수 있다.

```text
- 사용자 A와 사용자 B 사이의 연결 경로 찾기
- 특정 계정과 연결된 모든 리소스 찾기
- 특정 권한에 도달 가능한 IAM 주체 찾기
```

그래프 데이터베이스는 내부적으로 다양한 최적화와 질의 실행 계획을 사용하므로 단순히 BFS/DFS만으로 동작한다고 보기는 어렵다. 그러나 그래프 탐색 알고리즘을 이해하면 그래프 질의의 의미와 비용을 이해하는 데 도움이 된다.

## 5. GCP 리소스 계층 구조

GCP는 Organization, Folder, Project, Resource의 계층 구조를 가진다. 이 구조는 트리 또는 방향 그래프로 볼 수 있다.

```text
Organization
  ↓
Folder
  ↓
Project
  ↓
Compute Instance / Cloud Storage Bucket
```

BFS는 조직 전체에서 특정 깊이의 프로젝트나 리소스를 레벨별로 나열할 때 유용하다. DFS는 특정 Folder 아래의 모든 하위 리소스를 재귀적으로 탐색하는 데 적합하다.

IAM 정책 상속 관계도 그래프 탐색 관점에서 이해할 수 있다. 상위 조직이나 폴더의 정책이 하위 프로젝트와 리소스에 영향을 줄 수 있으므로, 정책 영향 범위를 분석할 때 탐색 개념이 중요하다.

## 보안 연결

## 1. 접근 경로 분석

보안에서 그래프 탐색은 “공격자가 어떤 경로로 민감 자산에 도달할 수 있는가?”를 분석하는 데 사용된다.

예:

```text
Internet
  ↓
Public Load Balancer
  ↓
Web Server
  ↓
Internal API
  ↓
Database
```

BFS를 사용하면 공격자가 최소 몇 단계 만에 데이터베이스에 도달할 수 있는지 분석할 수 있다. DFS는 특정 공격 경로를 끝까지 추적하며 각 단계의 취약점을 확인하는 데 유용하다.

---

## 2. IAM 권한 그래프와 권한 상승

클라우드 IAM 환경에서는 사용자, 역할, 정책, 권한, 리소스 간 관계를 그래프로 모델링할 수 있다.

```text
User A
  ↓ assume role
Role B
  ↓ attached policy
Policy C
  ↓ allows
s3:GetObject on Bucket X
```

권한 상승 분석에서는 DFS를 통해 특정 사용자가 다른 역할을 맡을 수 있는지, 그 역할이 더 높은 권한을 갖는지 탐색할 수 있다. BFS는 특정 고위험 권한에 가장 짧게 도달하는 경로를 찾는 데 사용할 수 있다.

보안 모범 사례:

- 최소 권한 원칙 적용
- 사용하지 않는 IAM Role과 Policy 제거
- Role assumption 경로 점검
- 권한 경로를 그래프로 시각화
- 고위험 권한에 도달 가능한 주체를 주기적으로 점검

---

## 3. 네트워크 세그멘테이션 검증

네트워크 세그멘테이션은 시스템을 여러 구역으로 나누고, 구역 간 통신을 제한하는 보안 기법이다. 그래프 탐색을 통해 특정 구역에서 다른 구역으로 도달 가능한지 검증할 수 있다.

예:

```text
User Subnet → Web Subnet → App Subnet → DB Subnet
```

DB Subnet이 외부에서 직접 접근 가능하다면 보안 위험이 크다. BFS를 사용하면 외부 네트워크에서 DB까지 도달 가능한 최소 경로를 찾을 수 있다. DFS는 특정 방화벽 규칙이나 라우팅 경로를 따라 깊이 있게 분석할 수 있다.

모범 사례:

- 보안 그룹과 네트워크 ACL을 함께 검토
- 인터넷에서 내부 DB로 직접 도달 가능한 경로 차단
- 관리 포트는 제한된 네트워크에서만 접근 허용
- 네트워크 접근 경로를 주기적으로 감사

---

## 4. 웹 크롤링과 보안 스캐닝

보안 스캐너는 웹 애플리케이션의 URL, 폼, API 엔드포인트를 탐색한다. 이때 BFS나 DFS와 유사한 전략이 사용될 수 있다.

BFS 방식은 애플리케이션의 넓은 표면을 빠르게 확인하는 데 유리하다. DFS 방식은 특정 기능 흐름을 깊게 따라가며 취약점을 찾는 데 유리하다.

주의할 점:

- 인증이 필요한 페이지를 탐색할 때 세션 관리 필요
- 무한 링크 구조 방지를 위한 방문 집합 관리 필요
- 크롤링 깊이 제한 필요
- 요청 속도 제한 필요
- 운영 시스템에 부하를 주지 않도록 스캔 범위와 시간을 제한해야 함

---

## 5. 그래프 탐색 구현 시 보안 이슈

그래프 탐색 알고리즘 자체는 기본 알고리즘이지만, 실제 시스템에 적용할 때는 다음과 같은 문제가 발생할 수 있다.

### 무한 루프

방문 여부를 기록하지 않으면 사이클이 있는 그래프에서 같은 정점을 계속 방문할 수 있다.

```text
A → B → C → A
```

모범 사례:

```text
visited set을 사용하여 이미 방문한 정점은 재방문하지 않는다.
```

### 메모리 고갈

BFS는 큐에 많은 정점을 저장할 수 있다. 매우 큰 그래프에서 메모리 사용량이 급격히 증가할 수 있다.

모범 사례:

- 탐색 깊이 제한
- 노드 수 제한
- 스트리밍 처리
- 페이지네이션
- 외부 저장소 활용

### 재귀 스택 초과

DFS 재귀 구현은 매우 깊은 그래프에서 호출 스택 한계를 초과할 수 있다.

모범 사례:

- 명시적 스택 사용
- 최대 깊이 제한
- 입력 그래프 크기 검증

### 서비스 거부 공격 가능성

사용자 입력으로 그래프 구조나 탐색 범위를 제어할 수 있는 시스템에서는 공격자가 매우 큰 그래프나 순환 구조를 만들어 서버 자원을 고갈시킬 수 있다.

모범 사례:

- 입력 크기 제한
- 탐색 시간 제한
- 요청당 리소스 사용량 제한
- 비정상적으로 큰 탐색 요청 차단
- 모니터링과 rate limiting 적용

## 면접 질문

**Q1. BFS와 DFS의 핵심 차이는 무엇인가요?**  
> 핵심 답변: BFS는 큐를 사용해 시작점에서 가까운 정점부터 레벨 단위로 탐색한다. DFS는 스택 또는 재귀를 사용해 한 경로를 깊게 탐색한 뒤 되돌아온다. BFS는 무가중치 그래프의 최단 경로에 적합하고, DFS는 사이클 탐지, 백트래킹, 위상 정렬 등에 자주 사용된다.

**Q2. BFS가 무가중치 그래프에서 최단 경로를 보장하는 이유는 무엇인가요?**  
> 핵심 답변: BFS는 시작 정점으로부터 거리 0, 1, 2, ... 순서로 정점을 방문한다. 따라서 어떤 정점을 처음 방문한 순간의 경로 길이는 시작점에서 그 정점까지 도달 가능한 최소 간선 수이다. 단, 간선 가중치가 없거나 모든 간선의 비용이 동일해야 한다.

**Q3. DFS를 재귀로 구현할 때 발생할 수 있는 문제는 무엇인가요?**  
> 핵심 답변: 그래프 깊이가 매우 깊으면 호출 스택이 초과될 수 있다. 또한 방문 처리를 하지 않으면 사이클이 있는 그래프에서 무한 재귀가 발생할 수 있다. 이를 방지하려면 visited 집합을 사용하고, 필요한 경우 명시적 스택으로 반복문 기반 DFS를 구현한다.

**Q4. 그래프에서 사이클을 탐지할 때 DFS를 어떻게 사용할 수 있나요?**  
> 핵심 답변: 방향 그래프에서는 정점 상태를 미방문, 방문 중, 방문 완료로 나눈다. DFS 중 방문 중인 정점을 다시 만나면 사이클이 존재한다. 무방향 그래프에서는 DFS 중 이미 방문한 이웃이 부모 정점이 아니라면 사이클로 판단할 수 있다.

**Q5. BFS와 DFS의 시간 복잡도와 공간 복잡도는 어떻게 되나요?**  
> 핵심 답변: 인접 리스트를 사용할 경우 BFS와 DFS 모두 시간 복잡도는 `O(V + E)`이다. 각 정점과 간선을 한 번씩 확인하기 때문이다. 공간 복잡도는 visited 저장에 `O(V)`가 필요하며, BFS는 큐에 최대 `O(V)`개의 정점을 저장할 수 있고, DFS는 재귀 스택 또는 명시적 스택에 최대 `O(V)`가 필요할 수 있다.
