# 트리 - 이진 트리, BST, AVL, Red-Black 트리, 힙(Priority Queue)

## 핵심 개념

## 트리(Tree)의 핵심 개념

트리는 계층적 관계를 표현하는 비선형 자료구조이다. 노드(Node)와 간선(Edge)으로 구성되며, 일반적으로 하나의 루트(root)에서 시작해 부모-자식 관계로 확장된다. 파일 시스템의 디렉터리 구조, 조직도, HTML DOM, 데이터베이스 인덱스, 컴파일러의 문법 트리처럼 “계층”이나 “부분 문제의 분할”을 표현할 때 매우 중요하다. 트리의 핵심 목적은 데이터를 단순히 나열하는 것이 아니라, 탐색·삽입·삭제·우선순위 처리 등을 더 효율적으로 수행할 수 있도록 구조화하는 데 있다.

## 이진 트리(Binary Tree)

이진 트리는 각 노드가 최대 두 개의 자식 노드를 갖는 트리이다. 왼쪽 자식과 오른쪽 자식이라는 구조적 제약이 있어 재귀적으로 정의하기 쉽고, 많은 고급 자료구조의 기반이 된다. 이진 탐색 트리, 힙, AVL 트리, Red-Black 트리는 모두 이진 트리 구조를 바탕으로 한다. 이진 트리는 순회 방식이 중요하다. 전위 순회는 루트를 먼저 방문하고, 중위 순회는 왼쪽-루트-오른쪽 순서로 방문하며, 후위 순회는 자식들을 먼저 방문한다. 특히 BST에서 중위 순회를 수행하면 정렬된 순서의 데이터를 얻을 수 있다.

## BST(Binary Search Tree)

BST는 이진 트리에 “왼쪽 서브트리의 모든 값 < 현재 노드 < 오른쪽 서브트리의 모든 값”이라는 정렬 규칙을 부여한 자료구조이다. 이 규칙 덕분에 평균적으로 탐색, 삽입, 삭제를 `O(log n)`에 수행할 수 있다. 하지만 입력 데이터가 이미 정렬되어 있으면 트리가 한쪽으로 치우쳐 높이가 `n`이 될 수 있고, 이 경우 연산 성능은 `O(n)`까지 나빠진다. 따라서 BST는 정렬된 데이터를 동적으로 관리하는 기본 개념이지만, 실제 시스템에서는 균형을 자동으로 유지하는 AVL 트리나 Red-Black 트리가 더 자주 사용된다.

## AVL 트리

AVL 트리는 스스로 균형을 유지하는 Self-Balancing BST이다. 각 노드에 대해 왼쪽 서브트리와 오른쪽 서브트리의 높이 차이를 의미하는 균형 인수(balance factor)를 관리하며, 일반적으로 그 차이가 `-1, 0, 1` 범위를 벗어나면 회전(rotation)을 통해 균형을 복구한다. AVL 트리는 매우 엄격하게 균형을 유지하므로 탐색 성능이 안정적으로 `O(log n)`이다. 다만 삽입과 삭제 시 균형 복구를 위해 회전이 자주 발생할 수 있어, 삽입·삭제가 매우 빈번한 환경에서는 Red-Black 트리가 더 선호되기도 한다.

## Red-Black 트리

Red-Black 트리는 노드에 Red 또는 Black 색상을 부여하고 특정 규칙을 만족시키는 Self-Balancing BST이다. AVL 트리보다 균형 조건이 덜 엄격하지만, 그 대신 삽입과 삭제 시 필요한 재조정 비용이 상대적으로 낮은 편이다. 대표적인 규칙으로 루트는 Black, Red 노드의 자식은 Black, 루트에서 리프까지의 모든 경로에 포함된 Black 노드 수가 같아야 한다는 조건이 있다. 이 조건 덕분에 트리 높이가 지나치게 커지는 것을 방지하며, 탐색·삽입·삭제를 모두 `O(log n)`에 수행할 수 있다.

## 힙(Heap)과 Priority Queue

힙은 완전 이진 트리의 형태를 가지며, 부모와 자식 사이에 우선순위 관계를 유지하는 자료구조이다. 최소 힙에서는 부모 노드가 자식 노드보다 작거나 같고, 최대 힙에서는 부모 노드가 자식 노드보다 크거나 같다. 힙은 전체 정렬을 보장하지 않지만, 최우선순위 원소를 빠르게 꺼낼 수 있다. 이 특성 때문에 Priority Queue의 대표적인 구현 방식으로 사용된다. 삽입과 삭제는 보통 `O(log n)`, 최솟값 또는 최댓값 확인은 `O(1)`에 가능하다. 작업 스케줄링, 이벤트 처리, 네트워크 패킷 우선순위 처리, 다익스트라 알고리즘 등에서 핵심적으로 쓰인다.

## 내부 동작 원리

## 1. 이진 트리의 구조와 순회

이진 트리는 각 노드가 최대 두 개의 자식을 가진다.

```text
        A
       / \
      B   C
     / \   \
    D   E   F
```

대표적인 순회 방식은 다음과 같다.

```text
전위 순회(Preorder):   A → B → D → E → C → F
중위 순회(Inorder):   D → B → E → A → C → F
후위 순회(Postorder): D → E → B → F → C → A
레벨 순회(Level):     A → B → C → D → E → F
```

전위 순회는 트리 복사나 직렬화에 유용하고, 중위 순회는 BST에서 정렬된 결과를 얻는 데 사용된다. 후위 순회는 디렉터리 삭제처럼 자식 노드를 먼저 처리해야 하는 작업에 적합하다. 레벨 순회는 큐를 이용해 너비 우선 탐색 방식으로 진행된다.

## 2. BST의 탐색, 삽입, 삭제

BST는 다음 규칙을 만족한다.

```text
왼쪽 서브트리 값 < 현재 노드 값 < 오른쪽 서브트리 값
```

예시:

```text
        50
       /  \
     30    70
    / \    / \
  20  40  60  80
```

값 `60`을 찾는 과정은 다음과 같다.

```text
60 < 50 ? 아니오 → 오른쪽으로 이동
60 < 70 ? 예     → 왼쪽으로 이동
60 == 60         → 탐색 성공
```

삽입도 탐색과 비슷하다. 새 값이 현재 노드보다 작으면 왼쪽, 크면 오른쪽으로 이동하다가 빈 위치에 삽입한다.

삭제는 세 가지 경우로 나뉜다.

1. **리프 노드 삭제**  
   단순히 해당 노드를 제거한다.

2. **자식이 하나인 노드 삭제**  
   삭제 대상 노드를 그 자식으로 대체한다.

3. **자식이 둘인 노드 삭제**  
   보통 오른쪽 서브트리의 최솟값, 즉 중위 후속자(in-order successor)로 대체한 뒤 해당 후속자 노드를 삭제한다.

예를 들어 `50`을 삭제할 때 오른쪽 서브트리의 최솟값 `60`으로 대체할 수 있다.

```text
삭제 전:
        50
       /  \
     30    70
          /  \
        60    80

삭제 후:
        60
       /  \
     30    70
            \
             80
```

## 3. AVL 트리의 균형 유지

AVL 트리는 각 노드의 균형 인수를 관리한다.

```text
Balance Factor = height(left subtree) - height(right subtree)
```

균형 인수가 `-1, 0, 1` 범위를 벗어나면 회전이 필요하다.

### LL 회전

왼쪽-왼쪽으로 치우친 경우 오른쪽 회전을 수행한다.

```text
삽입 후 불균형:
        30
       /
     20
    /
  10

오른쪽 회전 후:
       20
      /  \
    10    30
```

### RR 회전

오른쪽-오른쪽으로 치우친 경우 왼쪽 회전을 수행한다.

```text
삽입 후 불균형:
  10
    \
     20
       \
        30

왼쪽 회전 후:
       20
      /  \
    10    30
```

### LR 회전

왼쪽 자식의 오른쪽에 삽입되어 불균형이 발생한 경우, 먼저 왼쪽 자식에 대해 왼쪽 회전을 하고, 이후 현재 노드에 대해 오른쪽 회전을 한다.

```text
삽입 후:
      30
     /
   10
     \
      20

회전 후:
      20
     /  \
   10    30
```

### RL 회전

오른쪽 자식의 왼쪽에 삽입되어 불균형이 발생한 경우, 먼저 오른쪽 자식에 대해 오른쪽 회전을 하고, 이후 현재 노드에 대해 왼쪽 회전을 한다.

```text
삽입 후:
   10
     \
      30
     /
   20

회전 후:
      20
     /  \
   10    30
```

AVL 트리는 회전을 통해 높이를 낮게 유지하므로 탐색 성능이 안정적이다.

## 4. Red-Black 트리의 동작 원리

Red-Black 트리는 BST의 정렬 규칙에 색상 규칙을 추가한다.

대표적인 규칙은 다음과 같다.

1. 각 노드는 Red 또는 Black이다.
2. 루트 노드는 Black이다.
3. 모든 NIL 리프는 Black으로 간주한다.
4. Red 노드의 자식은 Black이다.
5. 임의의 노드에서 그 하위 NIL 리프까지 가는 모든 경로는 같은 수의 Black 노드를 가진다.

예시:

```text
          10(B)
         /     \
      5(R)     20(R)
      / \       /  \
   3(B) 7(B) 15(B) 30(B)
```

삽입 시 새 노드는 보통 Red로 삽입된다. 그 이유는 Black 노드 수 조건을 즉시 깨뜨릴 가능성이 상대적으로 작기 때문이다. 이후 부모와 삼촌 노드의 색상에 따라 다음 작업을 수행한다.

- 부모가 Black이면 종료
- 부모와 삼촌이 Red이면 색상 변경
- 부모는 Red, 삼촌은 Black이면 회전과 색상 변경

예를 들어 Red 노드가 연속되는 경우:

```text
불균형:
       30(B)
      /
   20(R)
   /
10(R)
```

오른쪽 회전과 색상 변경 후:

```text
      20(B)
     /    \
  10(R)  30(R)
```

Red-Black 트리는 AVL 트리보다 덜 엄격하게 균형을 맞추지만, 최악의 경우에도 높이를 로그 수준으로 제한한다.

## 5. 힙과 Priority Queue의 내부 동작

힙은 보통 배열로 구현된다. 완전 이진 트리이기 때문에 포인터 없이 인덱스 계산으로 부모와 자식 관계를 표현할 수 있다.

인덱스가 `0`부터 시작한다고 할 때:

```text
parent(i) = (i - 1) / 2
left(i)   = 2i + 1
right(i)  = 2i + 2
```

최소 힙 예시:

```text
배열: [1, 3, 5, 7, 9, 8]

트리:
        1
      /   \
     3     5
    / \   /
   7   9 8
```

### 삽입 과정: Bubble Up

새 원소를 배열 끝에 넣고 부모와 비교하면서 힙 조건이 깨졌다면 위로 올린다.

```text
삽입 전: [1, 3, 5, 7, 9, 8]
2 삽입: [1, 3, 5, 7, 9, 8, 2]

        1
      /   \
     3     5
    / \   / \
   7   9 8   2

2는 부모 5보다 작으므로 교환:
[1, 3, 2, 7, 9, 8, 5]
```

### 삭제 과정: Bubble Down

최소 힙에서 최솟값을 삭제할 때는 루트를 제거하고 마지막 원소를 루트로 옮긴 뒤, 자식과 비교하며 아래로 내려보낸다.

```text
삭제 전: [1, 3, 2, 7, 9, 8, 5]

루트 1 제거 후 마지막 원소 5를 루트로 이동:
[5, 3, 2, 7, 9, 8]

자식 중 더 작은 2와 교환:
[2, 3, 5, 7, 9, 8]
```

Priority Queue는 이 힙을 이용해 “가장 높은 우선순위의 작업”을 빠르게 꺼낸다.

## 실제 시스템 연결

## Linux

Linux 커널은 여러 곳에서 트리 기반 자료구조를 사용한다. 대표적으로 커널에는 Red-Black Tree 구현이 포함되어 있으며, 정렬된 데이터를 효율적으로 관리해야 하는 상황에서 활용된다. 예를 들어 타이머, 메모리 관리, 스케줄링 관련 구조 등에서는 정렬된 항목을 빠르게 찾거나 삽입·삭제하는 기능이 중요하다. 단, 커널 내부 구현은 버전별로 변경될 수 있으므로 특정 서브시스템이 어떤 트리만을 사용한다고 단정할 때는 커널 버전을 함께 확인해야 한다.

Linux 파일 시스템 계층 구조 자체도 트리 형태이다.

```text
/
├── bin
├── etc
├── home
│   ├── user1
│   └── user2
└── var
```

이 구조는 일반 트리의 대표적인 실제 사례이다.

## Nginx

Nginx는 이벤트 기반 서버이며, 내부적으로 타이머나 이벤트 관리에 트리 기반 구조를 사용한다. Nginx 소스에는 Red-Black Tree 관련 구현이 존재한다. 타임아웃 처리처럼 “가장 가까운 만료 시간”을 빠르게 찾고, 새로운 타이머를 삽입·삭제해야 하는 경우 균형 트리는 적합한 선택이다.

## Java / C++ 표준 라이브러리

Java의 `TreeMap`, `TreeSet`은 Red-Black 트리 기반으로 알려져 있다. 정렬된 키-값 저장소가 필요할 때 사용되며, 삽입·삭제·검색이 `O(log n)`이다.

C++의 `std::map`, `std::set`은 표준상 특정 구현 자료구조를 강제하지는 않지만, 일반적인 구현에서는 Red-Black 트리 같은 균형 이진 탐색 트리를 사용한다. 따라서 정렬 순회를 제공하면서도 로그 시간 연산을 지원한다.

Java의 `PriorityQueue`, C++의 `std::priority_queue`, Python의 `heapq`는 힙 기반 우선순위 큐의 대표적인 예이다.

## 데이터베이스와 검색 시스템

관계형 데이터베이스 인덱스는 보통 B-Tree 또는 B+Tree 계열을 사용한다. 이는 이진 트리와 다르지만, “정렬된 키를 트리 구조로 관리하여 검색 범위를 줄인다”는 점에서 같은 계열의 사고방식이다. 메모리 기반 정렬 구조에는 Red-Black 트리나 AVL 트리 같은 균형 이진 탐색 트리가 쓰일 수 있다.

검색 엔진이나 라우팅 테이블에서는 트라이(Trie), B-Tree, Prefix Tree 등 다양한 트리 구조가 사용된다. 트리의 핵심 가치는 검색 공간을 단계적으로 줄이는 데 있다.

## 운영체제 스케줄링과 힙

Priority Queue는 운영체제의 작업 스케줄링 개념과 밀접하다. 우선순위가 높은 작업을 먼저 실행하거나, 가장 빠른 마감 시간을 가진 작업을 먼저 처리해야 하는 경우 힙 기반 우선순위 큐가 적합하다. 실제 운영체제 스케줄러는 단순 힙만으로 구현되지 않는 경우가 많지만, “우선순위 기반 선택”이라는 개념은 힙과 직접적으로 연결된다.

## Docker와 트리 구조

Docker 이미지의 레이어 구조는 트리나 DAG 관점으로 이해할 수 있다. 하나의 베이스 이미지 위에 여러 레이어가 쌓이고, 여러 이미지가 공통 레이어를 공유할 수 있다. 엄밀히 말하면 일반적인 루트 트리라기보다 그래프적 성격도 있지만, 계층적 의존성을 이해하는 데 트리 개념이 도움이 된다.

```text
ubuntu base
   ├── app image A
   └── app image B
```

컨테이너 내부 파일 시스템도 Linux 파일 시스템 계층을 사용하므로 트리 구조를 그대로 따른다.

## Kubernetes

Kubernetes에서는 리소스 관계를 계층적으로 이해할 수 있다.

```text
Cluster
└── Namespace
    └── Deployment
        └── ReplicaSet
            └── Pod
                └── Container
```

이 구조는 엄밀한 자료구조 구현이라기보다는 관리 모델을 이해하기 위한 계층적 트리 관점이다. 또한 스케줄러는 여러 Pod 중 어떤 것을 먼저 처리할지 결정해야 하며, 이런 문제는 Priority Queue 개념과 연결된다. Kubernetes에는 Pod priority와 preemption 개념이 있으며, 우선순위가 높은 워크로드를 먼저 스케줄링하거나 낮은 우선순위 Pod를 축출할 수 있다.

## AWS

AWS에서 트리와 힙 개념은 여러 방식으로 연결된다.

- IAM 정책과 조직 구조는 계층적으로 설계될 수 있다.
- AWS Organizations는 계정과 Organizational Unit을 계층적으로 관리한다.
- S3 객체 키는 실제 디렉터리가 아니라 문자열 키 기반이지만, `/` 구분자를 사용해 트리형 폴더처럼 표현할 수 있다.
- 우선순위 작업 처리는 SQS 자체가 일반적인 단일 큐 기준으로 명시적 우선순위 큐를 제공하는 방식은 아니므로, 여러 큐를 우선순위별로 나누거나 애플리케이션 레벨에서 Priority Queue를 구현하는 방식이 사용될 수 있다.

## GCP

GCP에서도 조직, 폴더, 프로젝트, 리소스가 계층 구조를 가진다.

```text
Organization
└── Folder
    └── Project
        └── Resource
```

IAM 권한 상속을 이해할 때 트리 구조가 중요하다. 상위 노드에서 부여한 권한이 하위 리소스에 영향을 줄 수 있기 때문에, 권한 모델을 분석할 때 트리 순회와 상속 관계를 함께 고려해야 한다.

## 클라우드 네이티브 시스템에서 Priority Queue

클라우드 환경에서는 작업 큐, 이벤트 큐, 재시도 큐, 지연 큐가 자주 등장한다. 예를 들어 다음과 같은 경우 Priority Queue 개념이 사용될 수 있다.

- 긴급 알림 이벤트를 일반 로그 처리보다 먼저 처리
- 실패한 작업을 backoff 시간에 따라 재시도
- 스케줄링 대기 중인 작업을 우선순위 기준으로 선택
- 배치 작업에서 마감 시간이 가까운 작업을 먼저 실행

이때 힙은 “가장 우선순위가 높은 항목”을 빠르게 꺼내는 기본 구현 방식이 될 수 있다.

## 보안 연결

## 1. 알고리즘 복잡도 공격

BST는 균형이 깨지면 성능이 `O(log n)`에서 `O(n)`으로 악화될 수 있다. 공격자가 입력 순서를 조작해 트리를 한쪽으로 치우치게 만들면 서버의 CPU 사용량을 증가시키는 알고리즘 복잡도 공격이 가능하다.

예를 들어 단순 BST에 정렬된 데이터를 계속 삽입하면 다음과 같은 형태가 된다.

```text
1
 \
  2
   \
    3
     \
      4
```

이 경우 사실상 연결 리스트처럼 동작한다. 보안 관점에서는 외부 입력으로 자료구조를 구성할 때 단순 BST보다 AVL, Red-Black Tree, 해시 랜덤화, B-Tree 계열 등 최악 시간 복잡도를 고려한 구조를 선택하는 것이 좋다.

## 2. 우선순위 큐와 서비스 거부

Priority Queue는 중요한 작업을 먼저 처리하는 데 유용하지만, 우선순위 정책을 잘못 설계하면 낮은 우선순위 작업이 계속 밀리는 starvation 문제가 생길 수 있다. 공격자가 높은 우선순위 작업을 대량으로 제출할 수 있다면 일반 사용자의 작업이 처리되지 않을 수 있다.

모범 사례는 다음과 같다.

- 사용자별 rate limit 적용
- 우선순위 상승 권한 제한
- aging 기법으로 오래 기다린 작업의 우선순위 보정
- 큐 길이 제한 및 backpressure 적용
- 관리자 작업과 사용자 작업의 큐 분리

## 3. 비교 함수 취약점

BST, AVL, Red-Black Tree, Heap은 모두 원소 간 비교 연산에 의존한다. 비교 함수가 일관성을 만족하지 않으면 자료구조의 불변식이 깨질 수 있다.

비교 함수는 일반적으로 다음 성질을 만족해야 한다.

- 반사성 또는 동등성 처리 일관성
- 추이성
- 동일 입력에 대한 결정적 결과
- 예외나 부작용 최소화

예를 들어 `a < b`, `b < c`인데 `c < a`가 되는 비교 함수는 정렬 트리나 힙을 망가뜨릴 수 있다.

## 4. 권한 트리와 상속 문제

클라우드 IAM, 조직 구조, 파일 시스템 권한은 트리 형태로 상속되는 경우가 많다. 상위 노드에 과도한 권한을 부여하면 하위 리소스 전체가 영향을 받을 수 있다.

예시:

```text
Organization Admin 권한
└── Folder
    └── Project
        └── Production DB
```

상위 조직 단위에 강한 권한을 부여하면 운영 DB까지 접근 가능해질 수 있다. 따라서 최소 권한 원칙을 지키고, 권한 상속 경로를 주기적으로 점검해야 한다.

## 5. 힙 자료구조와 메모리 힙의 혼동 주의

알고리즘의 힙(heap)과 메모리 영역의 힙(heap)은 이름은 같지만 다른 개념이다. Priority Queue의 힙은 완전 이진 트리 기반 자료구조이고, 메모리 힙은 동적 메모리 할당 영역이다. 보안 문맥에서 “heap overflow”, “heap spraying”이라고 할 때는 보통 메모리 힙을 의미한다. 자료구조 힙과 직접적으로 같은 개념이 아니므로 혼동하지 않아야 한다.

## 면접 질문

**Q1. 이진 트리와 BST의 차이는 무엇인가요?**  
> 핵심 답변: 이진 트리는 각 노드가 최대 두 개의 자식을 갖는 구조적 제약만 가진 트리이다. BST는 여기에 왼쪽 서브트리 값은 현재 노드보다 작고, 오른쪽 서브트리 값은 현재 노드보다 크다는 정렬 규칙을 추가한 이진 트리이다. BST는 이 규칙 덕분에 평균적으로 탐색·삽입·삭제를 `O(log n)`에 수행할 수 있다.

**Q2. BST의 최악 시간 복잡도가 `O(n)`이 되는 이유는 무엇인가요?**  
> 핵심 답변: BST가 균형을 유지하지 않기 때문이다. 정렬된 데이터를 순서대로 삽입하면 트리가 한쪽으로 치우쳐 연결 리스트처럼 변할 수 있다. 이 경우 높이가 `n`에 가까워져 탐색, 삽입, 삭제가 `O(n)`이 된다.

**Q3. AVL 트리와 Red-Black 트리의 차이는 무엇인가요?**  
> 핵심 답변: 둘 다 Self-Balancing BST이지만 AVL 트리는 높이 차이를 엄격하게 관리하여 더 균형 잡힌 구조를 유지한다. 따라서 탐색 성능이 안정적이다. Red-Black 트리는 균형 조건이 AVL보다 완화되어 삽입·삭제 시 재조정 비용이 상대적으로 낮은 편이다. 탐색이 매우 많으면 AVL, 삽입·삭제가 많은 일반 목적 컨테이너에는 Red-Black 트리가 자주 사용된다.

**Q4. Red-Black 트리가 `O(log n)` 성능을 보장하는 핵심 원리는 무엇인가요?**  
> 핵심 답변: 색상 규칙을 통해 어떤 경로도 지나치게 길어지지 않도록 제한하기 때문이다. Red 노드는 연속될 수 없고, 루트에서 리프까지의 모든 경로는 같은 수의 Black 노드를 가져야 한다. 이 조건들이 트리 높이를 로그 수준으로 제한하여 탐색, 삽입, 삭제가 `O(log n)`에 가능하다.

**Q5. 힙이 Priority Queue 구현에 적합한 이유는 무엇인가요?**  
> 핵심 답변: 힙은 완전 이진 트리 구조를 유지하면서 부모-자식 간 우선순위 조건을 만족한다. 최소 힙에서는 루트가 항상 최솟값이고, 최대 힙에서는 루트가 항상 최댓값이다. 따라서 최우선순위 원소 확인은 `O(1)`, 삽입과 삭제는 `O(log n)`에 가능해 Priority Queue 구현에 적합하다.

## 관련 개념

- [[그래프]] - 트리는 사이클이 없는 연결 그래프의 특수한 형태로 볼 수 있다.
- [[DFS]] - 트리의 전위, 중위, 후위 순회는 깊이 우선 탐색의 대표적 응용이다.
- [[BFS]] - 트리의 레벨 순회는 너비 우선 탐색으로 구현된다.
- [[재귀]] - 트리는 자기 자신과 같은 구조의 서브트리로 구성되므로 재귀적 처리가 자연스럽다.
- [[이진 탐색]] - BST는 정렬된 탐색 공간을 절반씩 줄이는 이진 탐색의 아이디어를 동적 구조로 확장한 것이다.
- [[균형 이진 탐색 트리]] - AVL 트리와 Red-Black 트리를 포괄하는 상위 개념이다.
- [[B-Tree]] - 데이터베이스와 파일 시스템 인덱스에서 자주 사용되는 다진 균형 탐색 트리이다.
- [[Priority Queue]] - 힙의 대표적인 추상 자료형 응용이다.
- [[Heap Sort]] - 힙 자료구조를 이용해 정렬을 수행하는 알고리즘이다.
- [[Dijkstra Algorithm]] - 최단 경로 탐색에서 Priority Queue를 사용해 다음 방문 노드를 효율적으로 선택한다.
- [[스케줄링]] - 운영체제와 클라우드 시스템에서 작업 우선순위를 관리할 때 Priority Queue 개념이 활용된다.
- [[IAM]] - 클라우드 권한 상속 구조는 트리 형태로 이해할 수 있으며 보안 설계와 밀접하다.
