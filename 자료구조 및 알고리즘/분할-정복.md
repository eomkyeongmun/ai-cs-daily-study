# 분할 정복 - 문제를 쪼개서 해결하고 합치는 기법

## 핵심 개념

## 분할 정복(Divide and Conquer)

분할 정복은 큰 문제를 **더 작고 독립적인 하위 문제로 나누고(Divide)**, 각 하위 문제를 **재귀적으로 해결한 뒤(Conquer)**, 그 결과를 **합쳐서(Combine)** 원래 문제의 답을 만드는 알고리즘 설계 패러다임이다. 대표적인 예로 병합 정렬, 퀵 정렬, 이진 탐색, 거듭제곱의 빠른 계산, FFT 등이 있다.

분할 정복의 목적은 복잡한 문제를 직접 해결하지 않고, 구조적으로 더 단순한 문제들의 조합으로 바꾸는 것이다. 특히 입력 크기 `n`에 대해 문제를 절반 또는 일정 비율로 나눌 수 있을 때 시간 복잡도를 크게 개선할 수 있다. 예를 들어 병합 정렬은 배열을 절반씩 나누고 정렬된 결과를 병합하여 `O(n log n)` 시간에 정렬을 수행한다.

이 패러다임이 중요한 이유는 많은 고성능 알고리즘의 기반이 되기 때문이다. 단순 반복보다 재귀적 구조를 활용하면 문제의 본질적인 중복이나 구조를 명확히 파악할 수 있고, 병렬 처리와도 잘 맞는다. 각 하위 문제가 독립적이라면 여러 CPU 코어, 분산 시스템, 클라우드 환경에서 동시에 처리할 수 있다. 따라서 분할 정복은 알고리즘 이론뿐 아니라 대규모 데이터 처리, 병렬 컴퓨팅, 클라우드 기반 분석 시스템에서도 핵심적인 사고방식이다.

## 내부 동작 원리

## 내부 동작 원리

분할 정복은 일반적으로 다음 세 단계로 동작한다.

1. **Divide, 분할**
   - 원래 문제를 같은 형태의 더 작은 하위 문제로 나눈다.
   - 예: 배열을 왼쪽 절반과 오른쪽 절반으로 분할.

2. **Conquer, 정복**
   - 하위 문제를 재귀적으로 해결한다.
   - 하위 문제가 충분히 작아지면 직접 해결한다.
   - 이를 **기저 조건(Base Case)** 이라고 한다.

3. **Combine, 결합**
   - 하위 문제의 결과를 합쳐 원래 문제의 결과를 만든다.
   - 예: 병합 정렬에서는 정렬된 두 배열을 하나의 정렬된 배열로 병합한다.

### 일반적인 의사 코드

```text
DivideAndConquer(problem):
    if problem is small enough:
        return solve directly

    subproblems = divide(problem)

    results = []
    for each subproblem in subproblems:
        results.append(DivideAndConquer(subproblem))

    return combine(results)
```

### 다이어그램 설명

```text
                 원래 문제 P(n)
                      |
          -------------------------
          |                       |
      하위 문제 P(n/2)        하위 문제 P(n/2)
          |                       |
    -------------           -------------
    |           |           |           |
 P(n/4)     P(n/4)      P(n/4)      P(n/4)
```

위 구조는 재귀 호출 트리로 볼 수 있다. 각 레벨에서 문제 크기가 줄어들고, 가장 아래쪽에서는 더 이상 나눌 수 없는 작은 문제가 직접 해결된다. 이후 결과가 위로 올라오면서 결합된다.

### 병합 정렬 예시

```text
[8, 3, 5, 2]

분할:
[8, 3]        [5, 2]
[8] [3]       [5] [2]

정복:
[8], [3], [5], [2] 는 길이가 1이므로 이미 정렬됨

결합:
[3, 8]        [2, 5]
[2, 3, 5, 8]
```

병합 정렬의 점화식은 다음과 같이 표현된다.

```text
T(n) = 2T(n/2) + O(n)
```

두 개의 절반 문제를 해결하고, 병합 과정에서 전체 원소를 한 번 훑기 때문에 `O(n)`이 추가된다. 이 점화식을 풀면 시간 복잡도는 `O(n log n)`이다.

### 퀵 정렬과의 차이

퀵 정렬도 분할 정복 알고리즘이다. 피벗을 기준으로 작은 값과 큰 값을 나눈 뒤 각각 정렬한다. 다만 병합 정렬과 달리 결합 단계가 거의 필요하지 않다. 대신 분할 단계에서 피벗 기준 재배치가 핵심이다.

```text
[5, 1, 8, 3, 7]
피벗 5 선택

작은 값: [1, 3]
피벗: [5]
큰 값: [8, 7]

각 부분을 다시 정렬
[1, 3] + [5] + [7, 8]
```

퀵 정렬의 평균 시간 복잡도는 `O(n log n)`이지만, 피벗 선택이 계속 한쪽으로 치우치면 최악의 경우 `O(n^2)`이 될 수 있다.

## 실제 시스템 연결

## 실제 시스템 연결

분할 정복은 실제 시스템에서 대규모 데이터를 빠르게 처리하거나, 복잡한 계산을 병렬화하는 데 자주 활용된다.

### 1. 데이터베이스와 외부 정렬

대용량 데이터베이스는 메모리에 한 번에 올릴 수 없는 데이터를 정렬해야 할 때가 있다. 이때 **외부 병합 정렬(External Merge Sort)** 계열의 기법이 사용된다.

동작 방식은 다음과 유사하다.

```text
대용량 파일
   |
   |-- 메모리에 들어갈 크기의 청크로 분할
   |-- 각 청크를 개별 정렬
   |-- 정렬된 청크들을 병합
   |
최종 정렬 결과
```

이는 분할 정복의 전형적인 구조다. 전체 데이터를 작은 청크로 나누고, 각각 정렬한 뒤, 병합 단계에서 하나의 정렬된 결과를 만든다.

### 2. Linux와 정렬, 검색

Linux 환경의 여러 유틸리티와 라이브러리는 정렬과 검색 기능을 제공한다. 예를 들어 POSIX 계열 시스템에서는 C 표준 라이브러리의 `qsort()` 함수가 배열 정렬에 사용된다. 다만 C 표준은 `qsort()`의 내부 알고리즘을 특정하지 않으므로, 실제 구현이 항상 퀵 정렬이라고 단정할 수는 없다.

⚠️ 확인 필요: 특정 Linux 배포판 또는 특정 C 라이브러리 버전에서 `qsort()`가 어떤 정렬 알고리즘을 사용하는지는 구현체와 버전에 따라 다를 수 있다.

또한 이진 탐색은 정렬된 배열에서 탐색 범위를 절반씩 줄이는 방식으로 동작한다. 엄밀히는 결합 단계가 거의 없기 때문에 “감소 정복(Decrease and Conquer)”으로도 분류되지만, 문제를 더 작은 범위로 쪼개 해결한다는 점에서 분할 정복적 사고와 밀접하다.

### 3. MapReduce 모델

Google의 MapReduce 논문으로 널리 알려진 MapReduce 프로그래밍 모델은 대규모 데이터를 여러 조각으로 나누고, 각 조각에 대해 독립적으로 계산한 뒤, 결과를 모으는 방식이다. 이 구조는 분할 정복과 매우 유사하다.

```text
입력 데이터
   |
   |-- Split 1 -> Map
   |-- Split 2 -> Map
   |-- Split 3 -> Map
   |
Shuffle / Sort
   |
Reduce
   |
최종 결과
```

Map 단계는 분할된 데이터를 처리하고, Reduce 단계는 중간 결과를 결합한다. 따라서 대용량 로그 분석, 검색 인덱싱, 집계 작업 등에 적합하다.

### 4. 이미지, 오디오, 신호 처리

FFT, Fast Fourier Transform는 대표적인 분할 정복 알고리즘이다. 큰 신호 변환 문제를 짝수 인덱스와 홀수 인덱스의 작은 변환 문제로 나눈 뒤 결과를 결합한다. FFT는 디지털 신호 처리, 오디오 분석, 이미지 처리, 통신 시스템 등에서 널리 사용된다.

### 5. Nginx와 직접적 연결성

Nginx 자체의 핵심 동작을 단순히 “분할 정복 알고리즘”이라고 설명하는 것은 정확하지 않다. Nginx는 이벤트 기반 비동기 I/O와 워커 프로세스 모델을 중심으로 동작한다. 다만 대규모 트래픽 처리를 위해 작업을 여러 워커가 나누어 처리한다는 점은 “문제를 분할해 처리한다”는 넓은 의미의 설계 사고와 연결될 수 있다.

## 클라우드 연결

## 클라우드 연결

분할 정복은 클라우드 환경에서 특히 강력하다. 클라우드는 다수의 컴퓨팅 자원을 탄력적으로 사용할 수 있기 때문에, 하위 문제를 여러 노드나 컨테이너에 분산시켜 병렬로 처리할 수 있다.

### 1. Docker와 작업 분할

Docker 컨테이너는 애플리케이션 실행 환경을 격리하고 표준화한다. 분할 정복 관점에서는 큰 작업을 여러 개의 작은 작업으로 나누고, 각 작업을 독립적인 컨테이너에서 실행할 수 있다.

예를 들어 대용량 이미지 변환 작업이 있다면 다음과 같이 처리할 수 있다.

```text
전체 이미지 데이터셋
   |
   |-- Chunk A -> Container 1
   |-- Chunk B -> Container 2
   |-- Chunk C -> Container 3
   |
결과 수집 및 병합
```

각 컨테이너는 독립적으로 하위 문제를 해결하고, 이후 결과를 스토리지나 큐를 통해 모을 수 있다.

### 2. Kubernetes Job과 병렬 처리

Kubernetes에서는 `Job` 또는 `Indexed Job` 등을 사용하여 배치 작업을 여러 Pod로 나누어 실행할 수 있다. 이 구조는 분할 정복에 적합하다.

```text
Kubernetes Job
   |
   |-- Pod 0: 데이터 범위 0~999 처리
   |-- Pod 1: 데이터 범위 1000~1999 처리
   |-- Pod 2: 데이터 범위 2000~2999 처리
   |
결과 병합 단계
```

중요한 점은 각 Pod가 처리하는 데이터 범위가 명확히 분리되어야 하며, 마지막에 결과를 안정적으로 결합할 수 있어야 한다는 것이다.

### 3. AWS와 분할 정복

AWS에서는 여러 서비스가 분할 정복적 처리 구조와 잘 맞는다.

- **Amazon EMR**
  - Hadoop, Spark 같은 분산 데이터 처리 프레임워크를 실행하는 관리형 서비스다.
  - 대용량 데이터를 여러 파티션으로 나누어 처리하고 결과를 집계한다.

- **AWS Lambda**
  - 이벤트 단위로 함수를 실행한다.
  - 대량 파일 처리 시 S3 객체 단위 또는 메시지 단위로 작업을 나누어 병렬 실행할 수 있다.

- **Amazon S3**
  - 분할된 입력 데이터와 중간 결과, 최종 결과를 저장하는 데 활용된다.

- **Amazon SQS**
  - 하위 작업을 메시지로 분리하여 워커들이 병렬 처리하게 만들 수 있다.

### 4. GCP와 분할 정복

GCP에서도 유사한 구조를 구성할 수 있다.

- **Cloud Storage**
  - 분할된 데이터와 결과 저장.

- **Dataflow**
  - Apache Beam 기반의 데이터 처리 서비스.
  - 입력 데이터를 파티션 단위로 처리하고 변환 및 집계를 수행한다.

- **Dataproc**
  - Hadoop, Spark 클러스터를 관리형으로 실행할 수 있다.

- **Cloud Run**
  - 컨테이너 단위로 작은 작업을 처리할 수 있다.

### 5. Spark와 분할 정복적 사고

Apache Spark는 데이터를 파티션으로 나누어 여러 executor에서 병렬 처리한다. 예를 들어 `map`, `reduce`, `groupBy`, `sortBy` 같은 연산은 내부적으로 데이터를 분산 처리하고 필요한 경우 shuffle을 통해 결과를 재구성한다.

분할 정복과 완전히 동일한 알고리즘 구조는 아니더라도, 큰 데이터를 작은 파티션으로 나누고, 각 파티션을 처리한 뒤, 결과를 결합한다는 점에서 매우 밀접하다.

## 보안 연결

## 보안 연결

분할 정복 알고리즘 자체는 보안 취약점이라기보다 설계 방식이다. 하지만 이를 구현하거나 실제 시스템에 적용할 때는 여러 보안 및 안정성 이슈가 발생할 수 있다.

### 1. 재귀 깊이와 서비스 거부 공격

분할 정복은 재귀를 자주 사용한다. 입력이 악의적으로 구성되어 재귀 깊이가 지나치게 깊어지면 스택 오버플로우나 과도한 CPU 사용이 발생할 수 있다.

예를 들어 퀵 정렬에서 피벗 선택이 좋지 않으면 최악의 경우 재귀 깊이가 `O(n)`까지 증가하고, 시간 복잡도도 `O(n^2)`이 될 수 있다. 공격자가 이를 유도할 수 있는 입력을 제공하면 서비스 거부, 즉 DoS 문제가 발생할 수 있다.

모범 사례:

- 무작위 피벗 또는 median-of-three 같은 피벗 선택 전략 사용.
- 재귀 깊이 제한 설정.
- 최악의 경우를 방어하는 introsort 같은 정렬 방식 고려.
- 입력 크기 제한 및 타임아웃 적용.

### 2. 병렬 분할 처리에서 권한 문제

클라우드 환경에서 하위 작업을 여러 컨테이너, Pod, Lambda 함수로 나누어 실행할 경우 각 작업이 필요한 권한만 가져야 한다.

모범 사례:

- 최소 권한 원칙 적용.
- AWS IAM Role, Kubernetes RBAC를 세분화.
- 각 작업이 자신의 데이터 파티션에만 접근하도록 제한.
- 중간 결과 저장소의 접근 제어 설정.

### 3. 중간 결과 변조

분할 정복에서는 중간 결과를 결합하여 최종 결과를 만든다. 만약 중간 결과가 변조되면 최종 결과도 오염될 수 있다.

예를 들어 분산 로그 분석 시스템에서 일부 워커가 잘못된 결과를 제출하거나, 공격자가 중간 파일을 수정하면 최종 집계 결과가 왜곡될 수 있다.

모범 사례:

- 중간 결과에 대한 무결성 검증.
- 체크섬 또는 해시 사용.
- 객체 스토리지 버전 관리 및 접근 로그 활성화.
- 신뢰할 수 없는 워커의 결과를 검증하는 재계산 또는 샘플링 검증.

### 4. 데이터 분할 과정의 정보 노출

데이터를 분할할 때 민감 정보가 포함된 조각이 여러 시스템에 퍼질 수 있다. 이 경우 데이터 유출 면적이 넓어진다.

모범 사례:

- 민감 데이터 마스킹 또는 토큰화.
- 전송 중 암호화, 저장 시 암호화 적용.
- 데이터 파티션별 접근 권한 분리.
- 로그에 민감 데이터가 남지 않도록 관리.

### 5. 사이드 채널 가능성

일부 분할 정복 알고리즘은 입력 데이터에 따라 실행 경로나 시간이 달라질 수 있다. 암호학적 코드에서는 이런 시간 차이가 정보 유출로 이어질 수 있다.

예를 들어 조건 분기, 메모리 접근 패턴, 재귀 구조가 비밀 값에 따라 달라지면 타이밍 공격의 단서가 될 수 있다.

모범 사례:

- 암호학적 구현에서는 상수 시간 알고리즘 사용.
- 비밀 데이터 기반 분기 최소화.
- 검증된 암호 라이브러리 사용.
- 직접 구현 지양.

## 면접 질문

**Q1. 분할 정복이란 무엇이며 세 단계는 무엇인가요?**  
> 핵심 답변: 큰 문제를 작은 하위 문제로 나누고, 하위 문제를 재귀적으로 해결한 뒤, 결과를 결합하는 알고리즘 설계 패러다임이다. 세 단계는 Divide, Conquer, Combine이다.

**Q2. 병합 정렬이 분할 정복 알고리즘인 이유를 설명해보세요.**  
> 핵심 답변: 배열을 절반으로 계속 나누고, 길이가 1인 배열은 이미 정렬된 것으로 처리한다. 이후 정렬된 두 부분 배열을 병합하여 전체 배열을 정렬한다. 시간 복잡도는 `O(n log n)`이다.

**Q3. 퀵 정렬의 평균 시간 복잡도와 최악 시간 복잡도는 무엇이며, 왜 차이가 발생하나요?**  
> 핵심 답변: 평균 시간 복잡도는 `O(n log n)`, 최악 시간 복잡도는 `O(n^2)`이다. 피벗이 매번 균형 있게 분할하면 효율적이지만, 계속 한쪽으로 치우치면 하위 문제가 `n-1`, `0` 크기로 나뉘어 비효율적이 된다.

**Q4. 분할 정복과 동적 계획법의 차이는 무엇인가요?**  
> 핵심 답변: 분할 정복은 하위 문제가 대체로 독립적일 때 적합하다. 동적 계획법은 하위 문제가 중복되고, 최적 부분 구조가 있을 때 중복 계산을 저장하여 해결한다. 예를 들어 병합 정렬은 분할 정복, 피보나치 수열의 메모이제이션은 동적 계획법에 가깝다.

**Q5. 클라우드 환경에서 분할 정복을 적용할 때 주의할 점은 무엇인가요?**  
> 핵심 답변: 작업을 독립적인 단위로 잘 나누어야 하고, 결과 결합 방식이 명확해야 한다. 또한 중간 결과의 무결성, 실패한 작업 재시도, 권한 분리, 데이터 파티션 접근 제어, 네트워크 비용과 shuffle 비용을 고려해야 한다.

## 관련 개념

- [[재귀]] - 분할 정복은 하위 문제를 반복적으로 해결하기 위해 재귀 구조를 자주 사용한다.
- [[병합 정렬]] - 분할 정복의 대표적인 정렬 알고리즘이다.
- [[퀵 정렬]] - 피벗을 기준으로 문제를 나누는 대표적인 분할 정복 알고리즘이다.
- [[이진 탐색]] - 탐색 범위를 절반씩 줄이는 방식으로 분할 정복적 사고와 관련된다.
- [[점화식]] - 분할 정복 알고리즘의 시간 복잡도를 분석할 때 사용된다.
- [[마스터 정리]] - `T(n) = aT(n/b) + f(n)` 형태의 점화식을 분석하는 데 사용된다.
- [[동적 계획법]] - 하위 문제를 활용한다는 점은 비슷하지만, 중복 하위 문제 처리 방식에서 차이가 있다.
- [[병렬 처리]] - 독립적인 하위 문제를 동시에 처리할 수 있어 분할 정복과 잘 맞는다.
- [[MapReduce]] - 데이터를 나누어 처리하고 결과를 결합하는 분산 처리 모델로, 분할 정복적 구조와 유사하다.
- [[FFT]] - 신호 변환 문제를 작은 변환 문제로 나누어 해결하는 대표적인 고성능 분할 정복 알고리즘이다.
